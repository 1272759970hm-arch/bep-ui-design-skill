# 交互设计

> 本文件规定**页面级交互**：操作路径、状态完整性、异常场景、交互形态判据与方案决策。
> 组件级状态（某控件是否公开 disabled、hover 怎么写）以组件文档与 `validate-page.js` 为准，本文件不重复。

---

## 一、操作路径（四条基本路径）

设计任何页面时先写清路径，再决定控件。

### 列表路径

```
进入（带上下文筛选）
→ 筛选 / 搜索
→ 扫读列表（列序 + 状态可见）
→ 定位目标行
→ 查看详情 或 行内操作
→ 批量操作（可选）
→ 结果反馈（成功 / 部分成功 / 失败原因）
```

### 表单路径

```
进入（新增 / 编辑，带上下文）
→ 分组填写
→ 离开拦截（未保存时）
→ 校验（提交时定位第一个错误）
→ 提交（按钮 loading，禁止重复提交）
→ 结果（成功给出编号与去向 / 失败保留已填内容）
```

### 详情路径

```
进入（从列表 / 搜索 / 通知）
→ 概览数值
→ 分组信息
→ 动态记录
→ 动作（编辑 / 审批 / 关联单据）
→ 返回（保留来源筛选与位置）
```

### 审批路径

```
收到待办
→ 打开单据（摘要 + 明细 + 历史意见）
→ 判断（同意 / 驳回 / 转办）
→ 填写意见
→ 提交
→ 流转到下一节点（反馈：当前节点 / 下一节点 / 是否还能撤回）
```

**每条路径必须能回答：入口从哪来、中途能不能返回、出错怎么办、结束后去哪。**

## 二、状态完整性矩阵

页面（而非组件）必须覆盖的状态。★ = 必备，○ = 按场景。

| 状态 | 列表页 | 详情页 | 表单页 | 看板 | 弹层 |
|---|---|---|---|---|---|
| default 默认 | ★ | ★ | ★ | ★ | ★ |
| hover / focus | ★ | ○ | ★ | ○ | ★ |
| selected 选中 | ★（多选） | ○ | ○ | ○ | ○ |
| disabled 禁用 | ★ | ○ | ★ | ○ | ★ |
| loading 加载中 | ★ | ★ | ★（提交） | ★ | ★ |
| empty 无数据 | ★ | ○ | — | ★ | ○ |
| error 失败 | ★ | ★ | ★ | ★ | ★ |
| processing 处理中 | ★（批量） | ○ | ★ | ○ | ★ |
| permission denied 无权限 | ★ | ★ | ★ | ★ | ○ |
| partial 部分成功 | ★（批量） | ○ | ○ | ○ | ○ |
| read-only 只读态 | ○ | ★ | — | — | — |

**落地要求：**

- 每个状态都要有**可读的说明文案**和**下一步出口**（空态给主操作；失败给重试；无权限给申请入口）。
- 禁止只做 default + empty 两个状态。
- 批量场景必须设计「部分成功」：成功 N 条 / 失败 M 条 + 失败明细 + 行内重试。

## 三、异常场景清单（12 项）

| # | 场景 | 必须有 | 落地方式 |
|---|---|---|---|
| 1 | 无数据（首次） | 说明 + 主操作 | `bepEmptyState` + 新建按钮 |
| 2 | 无数据（筛选后） | 说明 + 清除筛选 | 空态文案区分「还没有」与「没找到」 |
| 3 | 数据加载失败 | 原因 + 重试 | 区块级失败态，非整页白屏 |
| 4 | 网络异常 | 提示 + 重试 | 操作级提示，保留已填内容 |
| 5 | 权限不足 | 说明 + 申请入口 | 独立无权限态（不用 404） |
| 6 | 操作失败 | 原因 + 重试 | `bepMessage` error 或行内提示 |
| 7 | 重复提交 | 按钮 loading + 禁用 | 提交期间锁定按钮，防双击 |
| 8 | 删除确认 | 二次确认 + 不可恢复提示 | `bepAlertModal` type=danger |
| 9 | 表单校验失败 | 定位第一个错误 + 错误清单 | 红边 + 行下文案 + 滚动定位 + 汇总提示 |
| 10 | 数据过长 | 截断 + 悬停/复制完整值 | 表格用 `bepTableText`，编号类不截断 |
| 11 | 数据为空值 | 统一占位符 | 描述列表空值用 `-`，不显示空白 |
| 12 | 数据量过大（万级以上） | 分页策略 + 合计 + 保存视图 | 见 §四·分页与大数据 |

## 四、交互形态判据

### 4.1 按钮 vs 链接

| 用按钮 | 用链接 |
|---|---|
| 触发动作、有状态变化（提交/删除/导出） | 只做跳转（详情、关联对象、帮助） |
| 需要主次层级 | 行内定位（表格里的「查看」） |
| 危险动作（二次确认） | 编号/名称跳转（编号即链接） |

### 4.2 页面跳转 vs 弹窗 vs 抽屉

| 判据 | 页面 | 抽屉 | 弹窗 |
|---|---|---|---|
| 字段/信息量 | 多（>20 字段或多分组） | 中（≤2 组） | 少（≤1 组，≤8 字段） |
| 是否需要上下文 | 强依赖（要边看列表边填） | 强（保留列表在侧） | 弱 |
| 操作频率 | 低频复杂 | 高频（列表内连续新增/编辑） | 一次性确认或极短表单 |
| 是否需要连续编辑 | 是（多条连续） | 是 | 否 |
| 页面层级 | 独立层级，可收藏/分享 | 中间层 | 临时层，处理完即关闭 |
| BeP 宽度 | 内容视窗自适应 | 420 / 640 / 800 | 420 / 640 / 800 |
| BeP 组件 | 页面 Card | 抽屉（`bepDrawer`） | 弹窗（`bepModal`） |

**选择顺序**：先问「会不会同时处理多条」→ 是则抽屉/页面；再问「信息量」→ 超一屏则页面；最后问「频率」→ 高频则抽屉。

**轻量确认**（删除 / 禁用 / 退出编辑 / 普通提示）一律用提醒弹窗（`bepAlertModal`），不用通用弹窗。

**层级上限**：弹层嵌套 ≤2 层；超过说明结构有问题，应改页面。

### 4.3 单选 vs 多选 vs 开关

| 控件 | 适用 | 不适用 |
|---|---|---|
| 开关（`bepSwitch`） | 立即生效的二元状态（启用态） | 需要点「保存」才生效的表单字段 |
| 单选组（`bepRadioGroup`） | 互斥、选项 ≤5 且需全部可见 | 选项多（用选择器） |
| 多选组（`bepCheckboxGroup`） | 互斥外的多选、≤8 项 | 选项多（用多选选择器） |
| 选择器（`bepSelect`） | 选项 6–15、需节省空间 | 二元状态 |
| 多选选择器（`bepMultiSelect`） | 已选需以标签回显 | 选项 ≤5（用多选组更直观） |

### 4.4 二次确认

| 必须确认 | 不必确认 | 需强确认（输入名称/编号） |
|---|---|---|
| 不可逆：删除、作废、终止 | 可逆：筛选、切换页签、暂存 | 影响面大：批量删除、批量推送、停用整组配置 |
| 影响他人：提交审批、发放、推送 | 只读操作 | 金额/权限类不可逆变更 |

### 4.5 批量操作

- 出现条件：列表数据量 ≥20 且存在重复性动作（推送、导出、审批、删除）。
- 必须有：全选 / 反选、已选条数可见、批量按钮在未选时禁用、选中后显示条数。
- 必须有结果反馈：全部成功 → toast；部分失败 → 失败明细 + 行内重试；全部失败 → 保留选中态便于重试。
- 禁止：批量按钮永远可点；批量后无反馈直接清空选中。

### 4.6 固定操作栏 / 吸顶 / 冻结列

| 场景 | 做法 |
|---|---|
| 表格超宽（列总宽 > 内容视窗） | 冻结标识列（左）+ 操作列（右），冻结列加对应侧阴影 |
| 表单超一屏 | 底部操作栏吸底，主按钮始终可触达 |
| 筛选条件多 | 已选条件以 chip 回显在筛选区上方，可单个清除 |
| 长列表扫读 | 表头吸顶 |

### 4.7 分页 vs 加载更多 vs 虚拟滚动

| 数据量 | 做法 |
|---|---|
| <1000 | 常规分页器（`bepPagination`） |
| 1000–10 万 | 分页 + 每页条数（20/50/100）+ 跳页 |
| >10 万 | 分页 + **保存视图**（常用筛选组合）+ 合计行 + 导出；禁止默认全量加载 |

### 4.8 筛选区展开与收起

**布局与折叠规则以 `filter-rules.md` 为准（三列等宽、标题区 112px、行高 64 等参数硬编码不可改）**，本表只做选择判断：

| 条件数 | 做法 |
|---|---|
| ≤2 且同行需要操作按钮 | 单行筛选（`bepFilterRow`），按钮紧跟条件右侧 |
| 3–5 | 三列网格展开态（`bepFilterGrid(..., false)`），不折叠 |
| ≥6 | 三列网格折叠态（`bepFilterGrid(..., true)`）：默认只显示前 5 个条件 + 「展开」，展开后显示全部 |
| 高频业务 | **产品建议**：把高频条件（如状态、费用期间）排在条件列表最前，折叠后仍可见；并按场景给默认值 |

必答：哪些条件是**每次都要用**的（排最前、给默认值），哪些是偶尔用的（折叠后隐藏）。

### 4.9 保存视图与列配置

出现条件（满足任一即建议）：

- 数据量 >1 万
- 用户有明显的固定查询习惯（如「未推送 NCC」）
- 列数 >8 且不同角色关注列不同

做法：保存「筛选 + 排序 + 列显示」为一组视图，下拉切换；默认视图为「全部」。

## 五、方案决策记录（A / B / C 对比）

存在多种合理方案时，不允许随机选，必须给对比与理由。

### 模板

```md
### 决策：<决策点，如「编辑用户信息」的交互形态>
| 方案 | 做法 | 优点 | 代价 | 适用条件 |
|---|---|---|---|---|
| A | 弹窗 | 轻快、不离开页面 | 空间小，字段多则滚动 | 字段 ≤8、单组 |
| B | 抽屉 | 保留列表上下文，可较长 | 遮住部分列表 | 2 组内、高频连续编辑 |
| C | 独立页面 | 空间充足、可分组、可分享 | 丢失上下文、多一次跳转 | 字段 >20 或多分组 |
**结论**：选 B。理由：3 组 12 字段（超弹窗舒适区）、需要对照列表操作（上下文强）、高频操作（每天多次连续编辑）。
**代价**：抽屉宽度取 640，表格右侧部分被遮挡；已在列表保留横向滚动与冻结操作列缓解。
```

### 判据权重（按序）

1. 信息量是否放得下（硬约束）
2. 是否需要上下文（硬约束）
3. 操作频率（决定效率优先级）
4. 是否连续编辑（决定能否原地完成）
5. 页面层级与可分享性

## 六、反馈与文案

| 场景 | 用什么 | 禁止 |
|---|---|---|
| 操作成功（轻量） | 全局提示（`bepMessage` success） | 用弹窗打断 |
| 操作失败（可重试） | 全局提示 error 或行内提示 | 只变色不说明原因 |
| 块状警告（表单内提示、重要说明） | 警告提示（`bepAlert`） | 用 `bepMessage` 近似（校验器禁止） |
| 不可逆确认 | 提醒弹窗（`bepAlertModal`） | 用浏览器 confirm |
| 表单整体校验失败 | 行内错误 + 汇总提示 | 只标红不给清单 |

**文案规则：**

- 说清「发生了什么 + 怎么办」：不好就写「保存失败，请检查网络后重试」，不写「操作失败」。
- 不可逆操作必须写明后果：「删除后不可恢复」。
- 数字与单位统一（金额含税标注、数量带单位）。
- 同一动作全系统同一动词（新建 / 发起 / 导入 / 推送）。

## 七、禁止事项

- 只设计 happy path（必须有状态与异常覆盖）
- 弹窗套弹窗超过 2 层
- 用忽略型反馈（无 toast、无状态变化）处理批量结果
- 危险动作无二次确认，或普通操作也弹确认（噪音）
- 批量按钮未选可用 / 已选不显示条数
- 提交按钮无 loading，可重复点击
- 用颜色单独表达语义（必须配文字或图标）
- 为了「更安全」给所有动作加确认弹窗
