# 01 · Product Thinking (需求理解 + 产品目标分析)

> Skill 强制流程 Step 1-2。
>
> **在选择任何组件之前，必须先想清楚这个页面为什么存在**。

---

## 5 Questions 框架（强制回答）

生成任何页面前，AI 必须先回答这 5 个问题：

| Q | 内容 | 允许推断？ |
|---|---|---|
| **Who** | 用户是谁？（角色 / 使用场景 / 心智）| ✅ 需说明推断依据 |
| **Where** | 用户从哪里来？（前一页 / 触发场景）| ✅ |
| **Why** | 用户为什么进入这个页面？（动机 / 情绪）| ✅ |
| **Task** | 用户来这里要完成什么核心任务？| ❌ 必须明确 |
| **Success** | 用户 / 业务 认为"成功"的定义是什么？| ❌ 必须明确 |

**规则**：如果无法回答 **Task** 或 **Success**，AI 必须**回到用户澄清**，不允许猜测。

---

## PRD Card 模板（Step 1 的必输出）

```
## Product Analysis Card

Who:      [用户角色，包含关键属性]
Where:    [从哪个页面 / 场景进入]
Why:      [动机描述，包含情绪]
Task:     [一句话说明核心任务]
Success:  [用户成功的定义] + [业务成功的定义]

推断说明: [如果 Who/Where/Why 是推断，说明依据]
业务 KPI:  [如果能推断，写出可能的核心指标]
```

---

## 示例：商品详情页

```
## Product Analysis Card

Who:      犹豫中的比价用户，从搜索/推荐进入，年龄 20-45，
          可能同时开着 3 个 App 比较
Where:    搜索结果页 / 首页推荐位 / 分享链接
Why:      看到感兴趣的商品，想深入了解 → 决策是否购买
Task:     快速判断"值不值得买" + 完成加购或立即购买
Success:  用户: 3 分钟内做出决策，无需跳走
          业务: 加购率 + 转化率 + 客单价

推断说明: 用户处于决策期而非闲逛期 → 页面必须服务决策
业务 KPI:  加购率、立即购买点击率、页面停留时长（越短越好）
```

---

## 示例：订单支付成功页

```
## Product Analysis Card

Who:      刚完成支付、心情放松的用户
Where:    支付页面 → 支付成功回调
Why:      确认订单已成功、了解下一步
Task:     确认支付成功 + 知道后续动作（等收货 / 查订单）
Success:  用户: 一眼知道"成功了、下一步做什么"，不再焦虑
          业务: 引导到订单详情 / 相关推荐，创造二次转化

推断说明: 支付成功是"高情绪时刻"，视觉应放松、有仪式感
业务 KPI:  订单详情跳转率、二次购买率
```

---

## 示例：物业报事页

```
## Product Analysis Card

Who:      业主，遇到公共区域问题（漏水/破损/异常）
Where:    App 首页 → 物业服务
Why:      家里或小区出问题，需要物业处理
Task:     快速描述问题 + 提交工单
Success:  用户: 30 秒内提交完成，无认知负担
          业务: 工单信息完整（位置/描述/图片）便于派工

推断说明: 用户可能焦虑（漏水场景），页面必须极简
业务 KPI:  提交率、信息完整率、工单处理时长
```

## 反模式：AI 常犯的错

### 反模式 1：直接跳过 Product Thinking

**症状**：用户说"做个 X 页"，AI 立刻开始画。

**后果**：视觉可能正确，但产品目标错位。做出来的页面不解决用户问题。

**修法**：任何页面生成前，**必须先看到 PRD Card 输出**。

---

### 反模式 2：Who 太模糊

**症状**："用户是使用 App 的人"。

**修法**：必须写出具体角色、场景、情绪。例：
- ❌ 用户是想买东西的人
- ✅ 犹豫中的比价用户，可能同时开着 3 个 App 比较

---

### 反模式 3：Task 过于宽泛

**症状**："完成购物"。

**修法**：Task 必须是一句话可执行的动作。例：
- ❌ 完成购物流程
- ✅ 快速判断"值不值得买" + 完成加购或立即购买

---

### 反模式 4：Success 只写业务视角

**症状**："提升 GMV"。

**修法**：必须写"用户成功"+"业务成功"双视角。用户成功 = 业务成功的前提。

---

## 与后续步骤的衔接

- **Task → Step 3 IA**：Task 决定 P0 是什么
- **Why (情绪) → Step 5 视觉基调**：焦虑 vs 放松 vs 兴奋
- **Success → Step 4 User Flow**：定义"完成"的终点在哪
- **Where → Step 5 首屏内容**：用户来源决定他期待看到什么

---

## AI 自查清单

Step 1 完成后必查：

- [ ] 5 个问题全部有答案？
- [ ] Task 是"一句话可执行的动作"？（不是抽象目标）
- [ ] Success 包含用户视角 + 业务视角？
- [ ] Who 有具体角色和场景？（不是"用户"两个字）
- [ ] 推断项是否说明了依据？

任何一项 fail → 补充或回用户澄清。
