# Design Decision Document (DDD) 模板

> Skill 强制流程 Step 6 的产物。
>
> **DDD 必须先输出并被用户 / AI 自己审核后，才能进入执行阶段（Step 7 组件选择）**。
>
> 违反 = 直接跳到组件拼装 = skill 违规。

---

## 完整 DDD 模板

```markdown
# Design Decision Document
## [页面名]

---

### ① Product Analysis (Step 1)
Who:      [用户角色 + 场景 + 情绪]
Where:    [来源]
Why:      [动机]
Task:     [一句话可执行]
Success:  [用户成功] + [业务成功]
推断说明: [如果有推断项，说明依据]
业务 KPI:  [如可推断]

---

### ② Page Type (Step 2)
页面类型: [首页 / 详情 / 反馈 / 表单 / ...]
混合特征: [如有]
骨架模板: [A Hero / B 主图 / C 清单 / D 表单 / E 反馈]
视觉基调: [信任 / 探索 / 放松 / 兴奋 / 尊贵 / 冷静]
密度: [高 / 中 / 低]

---

### ③ Information Architecture (Step 3)

| 优先级 | 信息 | 判断依据 | 视觉决策 |
|---|---|---|---|
| P0 | [信息 1] | [为什么核心] | [字号/颜色/位置] |
| P1 | [信息 2] | ... | ... |
| P1 | [信息 3] | ... | ... |
| P2 | [信息 4] | ... | ... |
| P3 | [信息 5] | ... | ... |
| P4 | [信息 6] | ... | ... |

自查:
- [ ] P0 数量 = 1
- [ ] P1 数量 ≤ 3
- [ ] 视觉映射符合规则
- [ ] 顶屏仅 P0 + P1

---

### ④ User Flow (Step 4)

1. Entry:      ...
2. See:        ...
3. Understand: ...
4. Act:        ...
5. Feedback:   ...
6. Next:       ...

认知负担自查:
- [ ] 3 秒理解
- [ ] 主 CTA 唯一
- [ ] Flow 无断链

---

### ⑤ Visual Strategy (Step 5)

视觉焦点: [具体位置 + 元素]

Rhythm 五要素:
- 大vs小: [具体表现]
- 强vs弱: [具体表现]
- 密vs疏: [具体表现]
- 图vs文: [具体表现]
- 色vs白: [具体表现]
(至少 3 项有明显对比)

主色应用: [出现在哪些位置]
运营元素: [大数字 / 倒计时 / 徽章 / ...]
反后台感自查: [清单全过 / 需修正]

---

### ⑥ What NOT to Include

主动排除项（写清楚删了什么、为什么）:
- [不加 X，因为...]
- [弱化 Y，因为...]
- [删除 Z，因为...]

**这一条比"加了什么"更重要**。

---

### ⑦ Component Plan (Step 7 预告)

基于以上决策，页面将由以下组件构成:

顶部:  [组件名 + 变体]
主体:  [组件名 + 变体]
中部:  [...]
底部:  [组件名 + 变体]

每个组件必须能回答:
- 它解决什么用户问题？
- 它支持哪个 P 级信息？
- 删了它 User Flow 会怎样？
```

---

## 使用规则

### 强制规则
1. **每个页面必须先输出完整 DDD**，才能进入 Step 7 代码生成
2. DDD 必须 **7 个 section 全部填写**，缺任一 section = 违规
3. 每个 section 的**自查清单必须全通过**，任一 fail = 回对应决策步骤重做

### 用户介入点
DDD 输出后是**用户介入的最佳时机**：
- 用户可以在这一步说 "P0 应该是 X 而不是 Y"
- 用户可以说"视觉基调改成 X"
- 修改 DDD **不需要重写代码**，只需重新执行 Step 7-9

### 简化情形（允许）
以下情况可以**输出简化 DDD**（保留 Product Analysis + Page Type + IA 三项，其他省略）：
- 用户明确说 "跟前面 X 页面一样的风格"
- 用户明确说 "简化版本，不用完整决策"
- 用户提供了完整 PRD 或原型（大部分决策已在原型里）

**不允许省略 DDD 的情况**：
- 首次生成某类页面
- 用户仅提供一句话需求
- 用户明确要求"设计"、"UX"、"完整"

## DDD 输出示例（商品详情页）

```markdown
# Design Decision Document
## 商品详情页 - 某数码产品

### ① Product Analysis
Who:      犹豫中的比价用户，20-45 岁，可能同时开着 3 个 App 对比
Where:    搜索结果 / 首页推荐 / 分享链接
Why:      对某商品感兴趣，评估"值不值得买"
Task:     3 分钟内决策 + 加购或立即购买
Success:  用户: 无需跳走完成决策 | 业务: 转化率 + 客单价
推断说明: 用户处于决策期而非闲逛期
业务 KPI:  加购率、立即购买点击率

### ② Page Type
页面类型: 商品详情
骨架模板: B 主图型
视觉基调: 信任 + 决策 + 转化
密度: 中（40% 图 40% 文 20% 留白）

### ③ Information Architecture
| P | 信息 | 依据 | 视觉 |
|---|---|---|---|
| P0 | 主图 | 用户第一决策点 | 375×375 顶屏 |
| P0 | 价格 | 决策关键 | 28px 红 Medium |
| P0 | 立即购买 | 完成 Task | Sticky 底红按钮 |
| P1 | 商品名 + 卖点 | 建立兴趣 | 16px Medium |
| P1 | 规格选择 | 决策必需 | Cell + 箭头 |
| P1 | 优惠 | 转化助推 | 醒目红 tag |
| P2 | 评价摘要 | 信任信号 | Cell "好评 98%" |
| P2 | 配送 | 决策信息 | Cell "顺丰次日达" |
| P3 | 详情图文 | 深度信息 | 下方长图 |
| P3 | 相关推荐 | 二次转化 | 页面底部 |
| P4 | 举报 | 合规 | ⋯ 菜单 |

### ④ User Flow
1. Entry: 从搜索进入，处于比价心态
2. See: 主图 + 价格
3. Understand: 下滑看规格、优惠、评价
4. Act: 立即购买（sticky 底部）
5. Feedback: 弹出选规格弹窗
6. Next: 加入购物车 / 直接下单

### ⑤ Visual Strategy
视觉焦点: 主图 (375×375 顶屏，独立空间)
Rhythm:
- 大vs小: 主图 375 vs 缩略图 60 ✓
- 强vs弱: 价格 28 红 vs 描述 12 灰 ✓
- 密vs疏: 详情图文密 vs 顶屏疏 ✓
- 图vs文: 顶屏 70% 图
- 色vs白: 底部 sticky 红 CTA + 主色 tag
主色应用: 价格、CTA、优惠 tag
运营元素: "已售 1024"、"限时立减"、原价划线
反后台感: 已建立视觉焦点 + 3 项 Rhythm 对比 ✓

### ⑥ What NOT to Include
- 不加 TabBar：详情页是漏斗深处，避免用户跳走
- 不加大 PageHeader "商品详情"标题：占用主图空间
- 弱化"分享"按钮：改为 ⋯ 菜单里的次要项
- 删除"商家其他商品"入口：避免转移注意力

### ⑦ Component Plan
顶部:  mkTopBar (title="商品详情", showBack=true, showMore=true)
主图:  mkImage (375×375, picsum)
价格:  自定义组合 (mkT ¥ 大字 + mkT 原价划线 + mkT 已售)
标签:  自定义 (mkTag "限时立减" danger + mkTag "满199包邮" warning)
标题:  mkTW (多行商品名) + mkT 副标题
规格:  mkInsetCard + 3 × mkCellRow ("已选/送至/服务")
评价:  mkInsetCard + mkCellRow ("好评98% ›")
详情:  mkInsetCard title="图文详情" + 若干 mkImage
底部:  mkBottomActionBar (buttons=[加购 warning, 立即购买 danger])
```

## AI 使用 DDD 的正确姿势

**错误姿势**：
- 直接开始写代码
- 只输出简短决策摘要
- 跳过某几个 section

**正确姿势**：
1. 收到需求 → 明确输出 "我先做 DDD"
2. 完整走完 5 步决策 → 输出完整 DDD
3. 询问用户是否需要调整（可选）
4. 用户 OK 后 → 开始 Step 7 代码生成
5. 代码生成后 → Step 10-13 Critic
