# 02 · Page Types (页面类型识别 + 各自设计策略)

> Skill 强制流程 Step 2。
>
> **不同页面类型必须使用不同的产品设计和视觉策略**。所有页面用同一骨架 = C 端感消失。

---

## 12 种 C 端页面类型

| 类型 | 用户核心动作 | 视觉基调 | 密度 |
|---|---|---|---|
| 1. 首页 | 探索 / 找入口 | 丰富、活力、多入口 | 高 |
| 2. 分类页 | 定位品类 | 清晰、结构感 | 中高 |
| 3. 搜索页 | 快速找到目标 | 极简、高效 | 低 |
| 4. 商品列表 | 浏览 / 比较 | 一致性、快速扫描 | 中高 |
| 5. 商品详情 | 决策 / 购买 | 信任、聚焦、转化 | 中 |
| 6. 活动 / 营销页 | 被打动 / 转化 | 冲击、氛围、情绪 | 高 |
| 7. 购物车 | 确认 / 结算 | 清晰、可信 | 中 |
| 8. 订单 | 查看 / 追踪 | 明确、状态感 | 中低 |
| 9. 支付 / 结算 | 完成付款 | 极简、无干扰 | 低 |
| 10. 反馈页（成功/失败/空）| 确认 / 引导 | 大留白、仪式感 | 极低 |
| 11. 个人 / 会员中心 | 管理 / 查看 | 秩序感 + 权益感 | 中低 |
| 12. 表单 / 设置 | 填写 / 配置 | 冷静、专注 | 低 |

---

## 每种页面的设计策略

### 1. 首页
- **P0**: 主推位（Banner / 大图入口）
- **P1**: 核心功能宫格、内容流入口
- **P2**: 促销位、活动位
- **视觉焦点**: Banner（占屏 30-40%）
- **必须**: 大 Hero + 宫格入口 + 内容流
- **禁止**: 全部用 InsetCard 装内容（会像后台系统）

### 2. 分类页
- **P0**: 品类导航
- **P1**: 品类下的精选商品
- **视觉焦点**: 品类图标 + 名称
- **典型骨架**: 左侧一级品类 tab + 右侧二级 + 商品

### 3. 搜索页
- **P0**: 搜索框（顶部粘性）
- **P1**: 历史 / 热搜 / 推荐
- **视觉焦点**: 搜索框 + 历史搜索
- **禁止**: 顶部大 banner（挤走搜索框）

### 4. 商品列表
- **P0**: 商品图 + 价格
- **P1**: 商品名、卖点标签
- **P2**: 销量、评价
- **视觉焦点**: 商品图（列表 40% 高度）
- **典型骨架**: 顶部 filter/sort + 商品网格或列表

### 5. 商品详情
- **P0**: 主图 + 价格 + 立即购买 CTA
- **P1**: 商品名、卖点、规格、优惠
- **P2**: 评价、配送、服务保障
- **P3**: 图文详情、推荐
- **视觉焦点**: 主图（顶屏 375×375）
- **必须**: sticky 底部购买 CTA
- **禁止**: 顶部 PageHeader 挤压主图空间

### 6. 活动 / 营销页
- **P0**: 主题 + 主推商品 / 优惠
- **P1**: 玩法说明、CTA
- **视觉焦点**: 大主视觉（占屏 50%+）
- **必须**: 沉浸式设计（色块、大字、动感）
- **禁止**: 用标准 TopBar + 白卡（会变成普通页）

### 7. 购物车
- **P0**: 商品列表 + 总价 + 结算 CTA
- **P1**: 步进器、选择、优惠
- **P2**: 猜你喜欢
- **视觉焦点**: 总价 + 结算按钮
- **必须**: sticky 底部结算栏

### 8. 订单页
- **P0**: 订单状态
- **P1**: 商品清单、金额
- **P2**: 物流、联系客服
- **视觉焦点**: 当前状态（大字 + 状态色）
- **必须**: 状态显式醒目

### 9. 支付 / 结算
- **P0**: 支付方式 + 金额 + 确认支付
- **P1**: 订单摘要
- **视觉焦点**: 金额（大字）+ 支付按钮
- **禁止**: 任何干扰性的营销位（用户已在漏斗末端）

### 10. 反馈页（成功 / 失败 / 空）
- **P0**: 状态图标 + 状态文字
- **P1**: 主 CTA（下一步动作）
- **P2**: 次要 CTA / 引导
- **视觉焦点**: 大反馈图标（80-120px）
- **必须**: 大留白（60%+）、单一信息、单主 CTA
- **禁止**: 塞多个入口

### 11. 个人 / 会员中心
- **P0**: 用户身份卡（头像 + 昵称 + 等级）
- **P1**: 常用功能入口（订单、券、地址）
- **P2**: 权益 / 积分
- **P3**: 设置
- **视觉焦点**: 用户身份卡（带背景装饰）
- **典型骨架**: Hero 用户卡 → 宫格 → 列表

### 12. 表单 / 设置
- **P0**: 表单填写区
- **P1**: 提交 CTA
- **视觉焦点**: 当前正在填的输入框
- **必须**: 冷静、留白、一屏一件事
- **禁止**: 装饰性元素（用户在完成任务，不需要氛围）

## 骨架模板参考

### 骨架 A：Hero 型（首页、活动、会员中心）

```
[TopBar 透明或半透]
[Hero 大区 (占屏 40%+)]
[入口宫格 / tab]
[内容流]
[底部 TabBar]
```

### 骨架 B：主图型（详情、支付成功）

```
[TopBar]
[主图 / 大图标 (顶屏聚焦)]
[核心信息]
[辅助信息 (卡片)]
[Sticky 底部 CTA]
```

### 骨架 C：清单型（购物车、订单列表、消息）

```
[TopBar]
[Filter/Tab 可选]
[清单卡 × N]
[Sticky 底部结算/CTA]
```

### 骨架 D：表单型（报事、投诉、设置）

```
[TopBar]
[PageHeader 大标题]
[分组 Card × N (每 Card 一个逻辑分区)]
[Sticky 底部提交]
```

### 骨架 E：反馈型（成功、失败、空）

```
[TopBar 简化]
[大留白]
[大反馈图标 + 文字]
[大留白]
[主 CTA + 次 CTA]
```

## AI 决策规则

Step 2 完成后，AI 必须：

1. 明确页面类型（12 种之一，允许"混合型"但需说明主导类型）
2. 引用对应骨架（A-E 之一，允许微调但需说明）
3. 明确该类型的 P0-P4 参考

**违规**：所有页面都用骨架 D（表单型）→ 首页、详情页都变得像表单。

---

## 常见误判

| 页面 | 常见误判 | 正确判断 |
|---|---|---|
| 支付成功 | 反馈页 → 加了一堆推荐 → 变成"支付成功首页" | 反馈页优先，推荐是 P3 |
| 会员中心 | 表单型 → 全部灰白 → 无权益感 | Hero 型，需要品牌感/尊贵感装饰 |
| 报事 | 详情型 → 顶部大图 | 表单型，简洁高效 |
| 购物车 | 列表型 → 只有清单 | 清单 + Sticky 结算，重点在转化 |
