# 生成示例

以下示例都是真实测试跑出来的产出，直接用浏览器打开对应文件夹里的 `index.html` 就能看效果（`styles.css` 要在同一个文件夹里）。

| 目录 | 页面 | 类型 | 备注 |
|---|---|---|---|
| `repair-request-form/` | 报修申请 | 表单页 | 第一次脱离 Figma MCP 的完整生成测试 |
| `task-execution/` | 任务执行 | 详情+列表混合页 | 按真实业务原型截图生成，配色替换成BEP-S真实品牌色 |
| `fulfillment-detail/` | 履约任务详情 | 详情页 | 按真实业务原型截图生成，正确排除了原型截图里的工具浮层元素 |
| `fulfillment-workbench/` | 履约工作台 | 看板+宫格+列表混合页 | 1:1还原真实业务原型截图（信息架构/数据不改动），金刚区图标首次用上 Solar Icons 真实提取SVG，底部导航图标全部为真实EXTERNAL_STANDARD资产（此前几个示例的Tab图标是AI_PROPOSED占位） |
| `clickable-prototype/` | 工单列表 → 详情 → 处理弹层 → Toast | **可点击原型**（2026-11 新增） | 第一个多屏可点原型模板：单文件零依赖、hash 路由+返回栈、Tab 切换、胶囊筛选、空态、弹层三种关法、Toast 自动消失。`html-prototype.md` 12 条交互契约的参考实现，产品可直接改 mock 数据复用 |
| `fulfillment-workbench-vibrant/` | 履约工作台(大厂C端视觉版) | 同上，风格化重做 | 内容/组件语义与`fulfillment-workbench/`完全一致，应用户"C端大厂设计风格、不要简约白色、icon更有设计感"的要求做视觉风格化：渐变头部、卡片投影、16px大圆角、图标渐变底盘放大到52px、数字圆形色块。**这是本skill第一次大规模使用USER_OVERRIDE背离默认的"无投影无描边、圆角6px"规则**，每处背离都在HTML的`data-bep-note`里标了USER_OVERRIDE/AI_PROPOSED，没有偷偷改成"BEP-S规范" |
| `tag-styles/` | 标签样式全览 | **规范速查页**（2026-11-05 新增） | 21 个带编号检查项：6 档色值总表、行内大/小档、卡片角标（含 0-8-0-8 几何示意）、尺寸规格、真实场景组合 + 语义选型表、4 个历史反例、可复制 CSS、交付前 6 条自检。颜色按真实设计稿 18 处标签实测（10% 同源浅底）落值 |
| `empty-states/` | 空状态（缺省页） | **规范 + 可交互演示**（2026-11-05 新增） | `index.html` 是规格与资产规则；`all-states.html` 是 8 场景在 375 手机壳内可切换的演示 + 并排全览。插画导出自组件库画板 138:3955 并已抠透明底（见 `assets/empty-states/`） |

这五个页面用的都是打包时刻的最新规则（卡片无投影无描边、真实 Ant Design 图标、主色 `#00B1B4`），如果你之后又更新了 Registry 数据，这几个示例不会自动跟着变，需要重新生成才会用上新规则——它们是"某个时间点的产出快照"，不是活的模板。

每个页面的 HTML 里都带 `data-bep-component`/`data-bep-status`/`data-bep-source`/`data-bep-verified` 这几个属性，标注了每个模块具体是真实组件复用、规范画板手搭、外部标准引用、还是纯 AI 兜底——想理解"这个 Skill 到底是怎么做判断的"，直接对着这几个页面的源码看会比看抽象规则更直观。
