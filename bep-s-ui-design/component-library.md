# BEP-S 组件规范

> 所有数值于 **2026-11** 从 Figma「BeP移动端组件-S端」（fileKey `vIpu7tb1dguui3QuqYETtM`）经 Dev Mode MCP 逐画板复核。
> 每个组件给出**视觉配方**（可直接落值的尺寸/圆角/填充/字级/状态），不再依赖"看着像"。

## 0. 使用顺序（强制）

生成任何页面/组件前，按此顺序取值，**不许跳步**：

1. 查本文件 **第 6 节 视觉配方总表** —— 有现成配方就直接用，不要重新推断；
2. 查本文件 **第 7 节 组件详规** —— 看状态、变体、禁止行为；
3. 数值缺口查 `design-tokens.md`；
4. 页面骨架查 `mobile-ui-rules.md` / `page-patterns.md`；
5. 三处都没有 → 标 `AI_PROPOSED` 并声明，**不许静默编一个数**。

> 这条顺序是 2026-11 新增。历史失败案例：搜索框圆角凭"卡片式圆角 4px"想象，实际规范是全圆角胶囊 18px；胶囊 Tab 选中态凭文档旧记录做成浅底，实际是实心品牌色。**根因都是跳过了第 1 步直接手写。**

## 1. 组件选用优先级（不可协商）

```
Figma 真实 Component / Component Set
  > 已有 Instance
  > 已有组件组合（第 8 节替代关系表）
  > 页面级模块
  > 新建组件（最后手段，仍必须复用 design-tokens 的颜色/字号/间距/圆角）
```

**禁止因为"视觉上更方便"重画库里已有的组件。** 组件复用率是**元素级**指标，不是页面级目标：页面构图（模块大小、间距、背景、视觉焦点）允许自由发挥，只要没有伪造组件真实性。

---

## 2. 命名陷阱（先看位置，再看名字）

**"标签栏"在库里对应两个完全不同的东西：**

| | Figma 真实名称 | 用途 | 位置 | 真实组件 |
|---|---|---|---|---|
| 底部导航 TabBar | `导航组件/标签栏/基础用法-…` `自定义个数-N个-…` | App 级一级入口 | 页面最底部，横跨全宽 | ✅ `INSTANCE`，8 个变体 |
| 页内分段 Tab | 画板"标签栏" `107:4417` | 页面内内容分类切换 | 内容区顶部 | ❌ `SPEC_FRAME`，无实例 |

判断口诀：**看位置、看它切换的是什么范围**，不是看中文叫什么。

---

## 3. SPEC_FRAME 与真实组件的处理

| 标记 | 能实例化 | 能作规格参考 |
|---|---|---|
| `REAL_COMPONENT` / `COMPONENT_SET` / `INSTANCE` | ✅ | ✅ |
| `SPEC_FRAME` / `GROUP` | ❌ | ✅ **必须照抄尺寸/颜色/字体/间距/圆角/状态** |
| `UNKNOWN` | ❌ | ⚠️ 标注待核实 |

`SPEC_FRAME` 的规则是：**结构必须照抄，创意不允许注入**。不能因为"反正是重搭"就顺手改成一个自己觉得更好看的样子。

---

## 4. 禁止「相似组件魔改」

目标组件不存在真实组件时，**不得**通过改尺寸/颜色/结构把最相似的组件伪装成目标组件：

- Input ≠ Textarea
- Button ≠ Card
- Checkbox ≠ Radio
- Cell ≠ Picker

正确流程：

```
目标组件 → 搜 Component → 搜 Instance → 搜 Component Set
  → 仍不存在 → 标 NOT_FOUND
    → 有 SPEC_FRAME → 按配方手工搭建，报告写"按 SPEC_FRAME 生成，非真实组件"
    → 无规范 → 列 Missing Component，禁止拿别的组件凑
```

若业务必须先出效果而做折中（如 Input 拉高模拟多行），报告里必须写"这不是 Textarea，是 Input 的非标准变形"，不能包装成"复用了真实组件"。

---

## 5. 组件状态必须独立验证

找到一个状态 ≠ 其他状态都有真实版本。每个状态分别搜索、分别记录，不能靠"家族完整性"脑补。

> 实测教训：全库只有"复选-默认-选中"是真实组件，**没有**"未选中"主组件；"主要按钮"图层名对应的主组件实际是"开关"。名字会骗人。

### 6.2 标签 Tab（页内分段）

**关键区分：库里有三种 Tab，选错就是错。**

| 类型 | 高度 | 文字 | 选中态 | 未选中态 | 适用 |
|---|---|---|---|---|---|
| **一级 Tab（下划线）** | 42px | 16px；选中 Medium `#00B1B4`，未选 Regular `#22262F` | 文字变品牌色 + 下方独立指示条 **24×2px 全圆角** | 同字号中性色 | 页面顶部大类切换 |
| **独立胶囊 Tab（单层筛选）** | 38px | 16px；选中 `#FFFFFF`，未选 `#22262F` | **实心 `#00B1B4` 底 + 白字** | 容器白底，文字深色 | 页面内单层状态筛选（全部/待响应/观察中/已归档） |
| **二级胶囊（多级标签内）** | 32px | 14px；选中 `#00B1B4`，未选 `#444F60` | **`rgba(0,177,180,0.16)` 浅底** + 品牌色字 | `#F2F3F5` 底 | 依附一级 Tab 的状态细分 |

**一级 Tab 规则**：文字**平分整行宽度**（不是左对齐+固定 gap）；指示条是独立元素（不是给文字加 border-bottom），固定 24×2px、全圆角、居中在文字正下方。

**胶囊组规则**：整个胶囊组是一个**白底全圆角容器**，选中项在其中实心填充（视觉像分段控件）；独立小胶囊之间间距 **16px**，一行放得下时平均分布；**胶囊不超过 3 个分类**，超过改用一级 Tab 或下拉。

**层级顺序**：范围大/总的分类用一级（上），范围小/细的用二级（下），不要凭视觉喜好倒置。

### 6.3 标签 Tag

| 规格 | 值 |
|---|---|
| 高度 | 大标签 22px（字 14px）／小标签 20px（字 12px） |
| 圆角 | 2px |
| 内边距 | 左右 8px |
| 浅底样式 | 主色 + **10% 透明度**（2026-11-05 实测更正，原记 16% 偏重）：品牌 `rgba(0,177,180,0.10)`、成功 `rgba(0,180,42,0.10)`、警告 `rgba(255,166,69,0.10)`、错误 `rgba(245,63,63,0.10)`、中性 `rgba(111,135,158,0.10)` |
| 文字色 | 与浅底同源的主色：`#00B1B4` / `#00B42A` / `#FFA645` / `#F53F3F` / **中性 `#6F879E`** |
| 内边距 | 内联标签 `px8 py2`；角标 `px8 py4`、高 27px |
| 角标形态 | 状态角标贴卡片**右上角**：`absolute top-0 right-0`，圆角 `rounded-tr-8 rounded-bl-8`（**不是四角 r2**），高 27 |

**语义区分**：分类信息标签（如"到店自提"）与业务状态标签（如"待自提"）**不能做成同一视觉**——状态用 10% 浅底+彩字（角标位），分类用中性石板灰 10% 底 + `#6F879E` 字（内联位）。**中性标签不是 `#F2F3F5` 底 + 深灰字**，那是未选中胶囊的样式，2026-11-05 实测更正。

> ⚠️ **别把 10% 和 16% 记混**：标签 10%、胶囊 Tab 二级 16%、页面筛选胶囊 14%。三者用途不同，混用会让标签看起来"发糊、发闷"。
>
> ⚠️ **两层事实（2026-11-05 核对组件库画板 107:3399「标签」后补充）**：组件库自己的标签画板实测**仍是 16%**（成功 `rgba(0,180,42,0.16)`+`#00B42A`、警示 `rgba(255,125,0,0.16)`+`#FF7D00`、错误 `rgba(245,63,63,0.16)`+`#F53F3F`、信息 `rgba(69,132,255,0.16)`+`#4584FF`、中性 `rgba(145,153,162,0.16)`+`#9199A2`，且混有旧品牌色残留 `rgba(0,109,155,0.16)`）——**这是组件库旧标准，不要回抄到页面**。真实业务页面（品质巡检稿 18 处标签）落地值一律是 **10% 同源浅底 + 同源实色字**，中性为石板灰 `rgba(111,135,158,0.10)`+`#6F879E`。页面输出按 10% 执行；组件库画板值仅存档备查。

### 6.17 空状态（缺省页）Empty State

> 2026-11-05 依组件库画板 `138:3955「35空状态」` Dev Mode 实测重写。**本条目取代原 §6.17 与 §6.28 两份旧记录**（旧记录把插画宽度记成 120，实测 225×195）。

#### 结构与间距（375 宽屏内）

```
┌─ 页面底色 #F7F8FA（不铺灰底、不加白卡） ─────────┐
│                                                  │
│              插画 225 × 195                      │
│                    ↓ 16                          │
│              标题 16px / 500 / lh24              │
│                    ↓ 8                           │
│         描述 14px / lh24 / #9199A2（≤2 行）      │
│                    ↓ 16（可选）                  │
│              [ 操作按钮 36px ]                   │
│                                                  │
└──────────────────────────────────────────────────┘
```

| 项 | 值 | 说明 |

#### 资产怎么取（三级路径，按可用性依次选）

1. **直接用 skill 自带资产**（最快）：上表 ✅ 的 3 张已在 `assets/empty-states/`，抠好透明底，直接 base64 内嵌。
2. **按 nodeId 自助导出**（其余 5 张，及以后新增的）：

3. **设计师手动 Export**：Figma 选中插画 instance → Export PNG → 1x（225×195 原尺寸），再走上面 `keyout.py`。

#### ⚠️ 白底陷阱（2026-11-05 被用户当场指出）

Figma 导出的 PNG **自带不透明白底**（实测纯 `255,255,255`，alpha 全 255——instance 框架底色被烘焙进去了）。直接贴到页面底色 `#F7F8FA` 上就是一块**白色方块**，视觉上非常突兀。

**必须抠成透明**：`assets/empty-states/keyout.py` 做边缘连通域抠图——从四边 BFS 清除与边缘连通的白，保留插画内部被轮廓包住的白色（吉祥物高光、白纸）。阈值 `min(r,g,b) >= 244`。页面底色接近白，1px 抗锯齿边看不出，无需羽化。

**不要用"全图白色一键透明"**：吉祥物身上有白色部件，那样会把它们打穿。

### 6.35 KV 信息块（卡中卡）KeyValue Block

> **组合型配方，不是真实组件**（组件库无对应 Component，状态标 `SPEC_FRAME`）。来源：品质巡检设计稿 `10293:34203`「任务信息」块实读 + 2026-11-04 落地校准。
> 用途：详情页头部卡内的字段明细区、弹层内的说明块。**不要**用于列表项（列表用 Cell）。

| 项 | 值 | 说明 |
|---|---|---|
| 容器底 | `#F7F8FA`（`color.fill.1`） | 不用 `fill.2`，避免与未选中胶囊同灰 |
| 容器圆角 | 8px | `radius.card` |
| 容器内边距 | **px16 / py12** | 不是四边 12 |
| 块内 gap | **8px**（标题行与字段组之间 12px） | |
| 字段行高 | **28px**（`py3` + 垂直居中） | **行距 = 28 + 8 = 36px** |
| 标签列 | 宽 76px，`#9199A2`（设计稿为 `#6F879E`，按 token 收敛） | 固定宽，不随内容伸缩 |
| 标签-值间距 | **12px** | |
| 值 | 14px `#22262F`，单行省略 | 设计稿该块用 16px；新页面按 token 用 14px |
| 字号例外 | 若 PRD/设计稿要求 1:1 还原（如对既有页面做改版），可用 16px，但**行高规格不变** | 需在交付说明里注明来源 |

**落值自检（三条全过才算对）**：① 连续两行的行距是 36px，不是 60px；② 灰块左右内边距是 16，不是 12；③ 标签列宽固定 76，长值单行省略不换行。

**HTML 实现陷阱（2026-11-04 实测）**：用 `dl/dt/dd` 排 kv 时，`<dl>` 的浏览器默认 `margin:16px 0` 不会被 flex 布局折叠，会把 36px 行距撑到 60px。必须显式 `margin:0`，行高用固定 `height` 而不是靠 `line-height` 顶。

**禁止**：白卡内再套白卡；把 kv 裸排在白底上（失去"这是数据区"的层级暗示）；四边等距 padding 12。

## 7. 各组件补充规则

### 导航栏 NavBar
- 触发：页面标题栏、返回、顶部操作。
- 禁止：全屏沉浸内容（图片预览）上叠加 NavBar；组件自带"全屏展示"变体已处理。

### 底部导航 TabBar
- 触发：App 级 2–5 个一级入口常驻切换。
- 禁止：拿它做页内分类切换；不要自造角标样式（用 6.9 的红点/气泡规则）。

### 页内 Tab
- 触发：单页内容分类切换。
- 禁止：与底部导航混用；胶囊超 3 个分类仍硬塞。

### 宫格 Grid
- 触发：首页/频道页图标入口矩阵。
- 禁止：入口需长文案说明时硬塞进 Grid，改用 Card。
