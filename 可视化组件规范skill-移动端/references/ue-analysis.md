# UE分析与整页方案规划

> v1.3.0离线执行：来源链接/节点仅供追溯，常规生成不调用Figma。使用本地模板和证据，执行方式以[离线组件合同](offline-components.md)优先；原规范的样式/口径仍有效，缺口不得伪装为完整还原。


本功能是用户明确要求加入的设计工作方法，不是从Figma画面推断出的项目业务规则。适用于新页面、原型转UI、整页优化与新增业务流程；目标是先解决用户如何理解数据和完成任务，再落实视觉规范。

## 1. 明确任务与依据

从需求、原型、业务说明和实际页面中确定：谁在什么场景下使用；最先要判断什么；看完以后需要比较、定位、下钻还是处理；页面属于主页概览、指标详情、经营诊断或精确查询。用户角色和下一步行动未提供时标为假设，不虚构用户访谈、调研结论、经营痛点或权限。

区分用户明确要求、原稿明文、样例观察、本次设计建议、待确认。用户清单决定内容，具体指标定义决定口径，模板和组件承载表达。发现模板不适配时调整槽位并说明理由；不能为了模板新增分类、删除字段或替换主指标。

## 2. 建立业务模型与字段去向

逐项核对原型全部字段，尤其主值、当期/累计、金额/比率、同比/环比、总量/分项、存量/流量、组织范围和时效。用[选型决策](chart-selection.md)判断数据关系；指标有例外时读取对应专项。

每个字段记录角色和去向：摘要、当前Tab、其他Tab、展开明细、排名、口径说明。字段可被重新分组，但不能无理由消失。关联关系未证实时，不把金额当构成、不把比率相加、不用余额累加成流入。

缺口只影响相应决策：缺少目标不画目标完成图，缺时间序列不造趋势。用户已授权模拟时使用明确标注的模拟数据并保持前后一致；没有授权时完成不依赖缺口的部分。只有会改变主任务、指标含义、权限或关键路径且无法合理判断的歧义才向用户提问，不能为普通排版选择新增确认环节。

## 3. 决定信息架构和优先级

确定模块、分组、默认状态和阅读顺序，并说明依据。通常从当前表现进入原因分析与精确查询；是否需要行动入口取决于真实业务，不默认添加催缴、导出或AI建议。

|决定|需要回答的问题|
|---|---|
|主信息|用户进入页面最先需要哪个结论？主值与比较、基数应如何相邻？|
|业务分组|哪些字段必须一起读？哪些适合同时比较，哪些应作为互斥Tab？|
|默认Tab/分类|最常用或当前任务所需的是什么？用户已指定的默认状态必须保留。|
|首屏和滚动|首屏是否能看清范围、主指标和下一模块线索？哪些内容滚动后出现？|
|渐进展开|哪些精确列、基数或长列表应展开查看？展开后如何保持上下文？|
|层级与返回|组织/排名/指标之间是否可下钻？返回时哪些条件应保留？|

不要为了“看起来简洁”把关键内容藏到多层展开；也不要让所有字段同等大、所有图同等高。布局预算与尺寸方法继续使用[整页布局](page-composition.md)，本文件只确定决策依据。

## 4. 将交互写成可执行的约定

围绕实际页面定义必要的用户路径，例如“选时间/组织 → 看概览 → 切分析维度 → 读图/展开 → 查排名/明细”。不是每个页面都需要所有步骤。

对每个影响数据的控件，简短记录：

|项|内容|
|---|---|
|触发与作用域|点哪个控件？影响全页、当前Tab、一个图还是一个明细？|
|更新对象|主值、比较期、图形、图例、明细、排名、更新时间中哪些同步？|
|保留/重置|切换后保留哪些筛选、选点、排序或展开项？哪些已无效需重置？|
|反馈与退出|如何看出已选、加载或无结果？如何收起、取消和返回？|
|权限/边界|首末名、无下钻权限、横滑边缘、负值/超百、0/缺失如何区分？|

已有源明文优先。未定义的点击、拖动、浮层、互斥展开或缓存行为可以提出本次方案并注明；不能只画箭头就称交互已实现。仅覆盖任务实际相关的空、加载、错误、无权限等状态，不为了凑状态图扩展需求。

## 5. 给出可审阅的设计取舍

输出关键决策和证据，不输出冗长的逐步思考。必须说明本次页面为何这样组织、图表解决什么问题、什么内容留在首屏、有哪些假设或未解决口径。

有实质取舍时比较可行方案并给出推荐，例如多主体独立收费率用多环还是共同尺度条形：依据精确比较任务、类别长度、数量与手机空间选择。不存在实质分歧的常规组件不必为凑数列多个方案。

质疑不合理需求时说明具体影响，并给出保留业务目标的方案。用户已明确选择时执行其选择并记录取舍，不擅自取消业务字段或改变范围。

## 6. 出图前的最小规划结果

新页面或整页重构必须在画高保真前形成以下简要结果，允许合并为一张表：

- 页面目标、核心任务和依据/假设。
- 信息架构、主次、默认状态和首屏安排。
- 全部业务字段的去向，包括各Tab与当期/累计。
- 每个图表的用户问题、数据关系、选择原因与精确读数位置。
- 关键路径、控件作用域、联动/重置及必要状态。
- 本次推荐方案、关键取舍、数据缺口和验证方式。

已有[页面规划表](page-composition.md#3-页面规划表)是布局记录的唯一模板，不再另造一份重复表格。用户要直接出UI时，简短告知核心决策并继续执行，规划不自动变成等待批准的阶段。对只改字号、图标、文案等明确局部任务，只分析该修改的影响，保留其他区域，不强制全套重构。

## 7. UI完成后回到UE验收

先沿核心任务核对：能否判断当前范围与状态、找到关键值、理解图表、取得精确读数并完成所需查询/返回；再对照字段映射确认没有遗漏，尤其当期/累计与同环比。

检查分析结果是否真正落到UI：不能文档写“首屏看主值”但实际被筛选和大图挤走，不能写“可查全部列”却只交一张裁掉右列的静态图。交付简短设计决策说明、完整页面及必要状态，标明假设、静态示意与未验证交互；不将生成成功、结构检查或用户未反馈等同体验验收通过。

## 边界用例

- **金额、设备数、使用率混合的经营看板**：先分任务与量纲，再决定概览/业务Tab/趋势；不把不同单位塞入一个环。
- **有总金额、无分类和时序的原型**：完成主值、比较和已知明细；不为体现设计能力增造分类或曲线。
- **手写业务清单＋指定模板**：业务清单逐项映射，模板只决定合适的视觉骨架；不能补上模板层级却漏掉当期/累计。
- **原稿说明与样例矛盾**：保留冲突和适用版本，依明确的当前需求决定本次表达；未确认业务算法不写成事实。
