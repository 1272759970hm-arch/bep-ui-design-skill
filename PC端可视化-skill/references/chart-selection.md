# 图表选型：先判断数据关系

> v1.3.0离线执行：来源链接/节点仅供追溯，常规生成不调用Figma。使用本地模板和证据，执行方式以[离线组件合同](offline-components.md)优先；原规范的样式/口径仍有效，缺口不得伪装为完整还原。


**选型落地约束：** 选定表达后，必须定位并以对应规范原生图表组件/完整图表组为底适配，不以同类型的自绘图替代。记录源节点与产出对应；数据几何调整不等于样式重建。详见[原生组件复用核对](implementation-conformance.md#原生图表组件为底用户明确要求)。缺少适用底稿时报告，不为凑图换错业务关系或自行降级。

本文件是基于已读一看样例形成的**选型分析与实施建议**。已读4424:69842的单指标环/独立多环五态，以及4424:70735项目实收的构成、趋势与同期对照；选型建议不冒充原稿强制规定。原稿趋势粒度明文与待确认项见[项目实收图表模式](receipt-chart-patterns.md)。其他图形的历史样式来源见[图表类型](chart-types.md)，本轮未全部重读。

## 选图纠错：先确定要比较的关系，再选编码

2026-10-28实测教训：类型合法不代表对当前任务最有价值。不能按“有百分比→环图、数量→柱图、单位不同→拆图、用户发来环图→所有页面换环”选择。参考图用来识别业务组合与表达办法，不能代替当前业务关系的核对。

对存在实质选型取舍的图，在出图前保留一条简短决策：**用户要回答的问题 → 指标关系与依据 → 选用图形及其编码 → 为什么另一可行图形优先级更低 → 数据缺口如何局部处理。** “美观、直观、适合移动端”不是单独成立的选型理由。常规无争议读数不必凑两个方案。

|本次任务|曾经选错的判断|应采用的选型判断|
|---|---|---|
|资金与收益、本期与累计一起分析|自行将两项收益归一化为一个环；用大面积强调97%/3%，回避资金参照与期间关系|先辨明整体/分项/参照/期间。任务需要整体参照和分类比较时，比较横向分段/参照组合与构成环的效用，并把本期/累计明细关联到分类。只有主要问题是构成占比，环才优先；只有主要问题是金额大小，独立条才优先。不强造目标、贡献率或“其他收益”|
|设备规模、来源与利用效率|设备统计放TOP5横条，下方又做排名；把“有数量”误解成“需要比较项目”|总量和来源是构成问题，来源互斥且与总量同口径时可用构成环；日均使用率是独立比率，可用紧凑进度条；TOP5只回答对象排名，不替代规模/来源分析。存量、当期新增、累计落桩不自动等价|
|五项设备指标联合看趋势|先按单位分组，导致默认只看一项；随后机械拆成两图|先判断用户是否要同时观察五项变化。本任务采用单图五系列、左数量右百分比、共同时间轴/选点和五行读数，数量项在前、比率项在后。单位不同要求轴编码清楚，不自动要求拆图；独立任务才考虑分图|

上述是本次业务判例，不是所有资金页都用横向条、设备页都用环、趋势都用双轴的普遍规定。比率/金额/数量只是字段属性，构成/对照/变化/排名才是要被表达的关系。

数据缺口只阻止不满足前提的编码，不允许借此改写主任务。用户允许模拟时，可用明确标注的业务假设形成可评审方案；未允许模拟时，保留已有关系及精确读数并标清待补项。来源中的66.6%等示例没有已确认分母/目标时，不当成正式完成率。

## 已核查业务模式的快速选表

整体参照＋分类联动分析见[4424:80978组合样式](profit-composite-chart-pattern.md)。选图包括对应业务组件结构，不止几何类型；参照、实际、分类、选中详情与明细要共同确定。不要以普通100%堆叠条和常显总表替代源组合。

|需求词与真实问题|选表入口|判断关键|
|---|---|---|
| 微信代扣：住户规模与签约/解约率怎样同时变化 | [微信代扣组合图](payment-business-chart-patterns.md#1-微信代扣独立比率环双轴柱线) | 户数用同轴分组柱，比率用另一百分比轴折线；时间对齐、单位明确，离线用 `contractTrend`；只看比率可单用折线 |
| 预存：金额贡献、余额还是活动数量 | [预存模式](payment-business-chart-patterns.md#3-项目预存流入金额余额和活动数分开) | 分类金额可用构成；余额与流入不能混算；活动数量独立读数；年/月，无按日 |
| 欠费：主体/账龄分布，或月净增减与累计 | [欠费模式](payment-business-chart-patterns.md#4-项目欠费账龄结构与余额变化) | 合法金额分类用构成/有序条形；月趋势用折线，净增减可考虑正负柱；历史日查询不推导小时轴 |
| 收费率：整体、主体还是变化 | [收费率模式](payment-business-chart-patterns.md#2-项目收费率整体比率独立主体比率趋势) | 单环/独立多环/百分比趋势分别承担不同问题；去掉按日，不对百分比累计求和 |
|收缴/追缴、费用科目、渠道：各贡献多少金额|[项目实收构成](receipt-chart-patterns.md#1-用业务问题选择分析图表)|共同整体、互斥分类、总额完整；成立才用构成环，精确比较可换横条|
|账单主体：贡献多少金额|[三分类构成及展开](receipt-chart-patterns.md#2-环图的中心值分类明细和比较)|主体分类的金额份额；选中分类金额不自动等于总额|
|账单主体：各自收费率多少|[独立多环/比率状态](chart-interaction-spec.md)|各自有分母，不相加成100%；精确比较可用共同尺度条形|
|实收/分类随时间变化；本期与同期对照|[趋势粒度与控制](receipt-chart-patterns.md#3-趋势的时间粒度与累计单值)|先定累计/单值，再定月/日/小时粒度、系列与同期；按日实收仍待确认|

同一个“账单主体”词语可对应金额构成、独立收费率或时间趋势，不能仅按关键词/组件名称选图。

## 先回答五个问题

1. 用户要判断什么：当前水平、变化、差异、构成、目标、排名还是精确查询？
2. 数据是什么关系：时间序列、独立类别、互斥整体、各自比率、实际/目标、阶段、增减贡献？
3. 必要数据是否齐全：单位、时点、粒度、类别、分子分母、目标/基数、负值和超百含义？
4. 页面如何读：主指标和参照放哪里，图表回答哪个问题，精确明细如何对应，手机宽度是否允许？
5. 有哪些状态和交互：选中/展开、缺失/0、负值/超百，以及切换时哪些内容要同步？

业务字段决定图形；已有模板只提供合适槽位。图表必须提供数值之外的信息，不能为了“可视化”增加无业务依据的分类或模拟维度。用户明确授权模拟时注明来源，模拟与真实值保持可追查区分。

## 决策表

|业务问题|优先图形|需要的数据|使用约束/换图条件|
|---|---|---|---|
|一个指标现在多少|主值＋同环比/参照；必要时小图|当前值、单位、期间；比较有基数|只有单值时不虚构折线；无需强配一个大环|
|随时间怎样变化|折线；突出总量时谨慎用面积|有序时间＋相同口径数值|两点只能说明两点变化，不制造曲线波动；缺失不补0；累计与当期标清|
|各类差多少/谁最高|水平条形；短标签可用柱形|同单位、可比较类别与数值|数量多或标签长时优先水平条/排名表；共同零基线；正负跨零|
|同类本期与同期差异|分组柱/条或对比折线|对齐分类或时间、两个可比较期间|需要表达正负方向时使用 `signedPeriodBars`；不要用堆叠伪装两期构成；比较窗口先核实|
|同一整体由什么组成|构成环/饼、堆叠条|互斥分类、非负值、可核对总量|独立收费率和不同量纲不能拼环；含负份额或合计关系不成立时先校验或改条形明细|
|一个比率/完成度离100%多远|单指标进度条/比率环|指标及其分母/目标；100%含义|核心单指标可用环；首屏紧凑或需精确比较时优先条形；参照69842五态|
|少量对象各自完成度怎样|独立多环，或同尺度分组进度条|每个对象各自分子分母、共同参考尺度|不相加、不当整体构成；精确比较、类别增多或手机标签拥挤时改条形表|
|实际值距业务目标多远|带目标标记的进度条/子弹图|实际值、目标值，必要时区间阈值|未提供目标时不能把行业猜值当目标；超目标需保留原数值|
|总量如何被增减因素改变|瀑布图；仅看正负规模可用正负柱|期初、互斥增减项、期末及可核对加总|不能把无加总关系的指标做瀑布；正负柱不表示完整桥接关系|
|类别总量和内部结构怎样变化|堆叠柱；只比结构时用100%堆叠|每类总量与其互斥组成|中间分段不易精确比较；需要精确比某项时改分组图；100%图不能承担绝对规模对比|
|阶段流失/转化|漏斗或阶段条形|同一人群/业务对象、明确阶段顺序与口径|独立业务指标、非连续阶段不能凑漏斗|
|查精确值、多字段和名次|表格/排名表＋可选小条|组织范围、排名指标、精确列值与权限|一看同级/下辖排名权限不同；不可因手机窄删业务列，保留横滑/展开方案|

散点、热力、地图等只有在分别存在“数值相关性”“二维矩阵密度”“地理分布”问题且数据齐备时考虑；它们不是当前两个规范区已确认的组件，不借用普通环图规则声称已有样式。不要无需求扩展成必备图表库。

## 容易混淆的三类环

|类型|分母/整体|可以相加吗|异常值处理|
|---|---|---|---|
|收费金额分类构成环|所有分类共同组成同一总额|分类额可加；份额应合计约100%（允许舍入）|负数/超总额先核对构成资格，不套进度环超百样式|
|收费率单环|当前指标的应收、目标或已确认分母|只是一个比率，不能与旁边金额相加|保留负/0/正常/100/超百；缺失与分母0单独处理|
|账单主体独立多环|每类各有自己的应收/目标|各类百分比不能相加成总收费率|各环独立判断五态；总体值由业务定义，不能简单平均|

## 在实际页面中判断

- 两轮充电经营情况：按[最新资金组合条口径](charging-funding-bar.md)，实际收益＝充电收益＋增值收益；总资金流水＝实际收益＋未计入部分。两色块合计占总流水的比例为主读数，灰色为未计入余量；分类切换不改变合计范围。复用用户指定完整业务组，不把三个金额当三个扇区、不把两色块归一化铺满轨道，也不将占比称为目标完成率。
- 设备统计：用户明确设备数量＝自有项目落桩数＋外拓项目落桩数；总量与来源用构成关系分析，使用率独立表达。存量和当期新增/累计落桩仍区分，日均使用率不并入设备数量构成。无对象排名任务时，不用TOP5替代本模块。
- 设备趋势：本任务已明确联合看五项，采用[单图双轴组合](trend-series-pattern.md)，数量与比率各用自己的轴，默认五项全部展示。核对每个序列的统计窗口，不将源日均51.16%与单日53.08%当同一读数；不同单位不自动拆图。跨轴高度不能用来比较数值大小或证明相关性。
- 指标详情：先保留业务清单的所有字段，再选择图形；不能因模板有环就添加支付渠道等需求外分类。

## 选型后必须记录

为每个图表写清“用户问题 → 数据关系 → 图形选择与原因 → 图形编码/单位 → 精确读数位置 → 状态/交互 → 数据来源与缺口”。检查图表、摘要与明细是否回答同一业务问题，而不是只验图形外观。

维护选型规则时，定向检查同一业务在主选型文件、专项与示例中的结论。补丁不得留下相反指导，例如专项要求联合双轴、主入口仍要求分组；源样例、当前用户选择与本次建议分别标明，不靠继续增加版本号掩盖冲突。
