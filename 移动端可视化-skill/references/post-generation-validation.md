# 生成后自动校验与修复

v1.3.4-trial.2 · 默认流程，不需要用户再要求检查。

## 执行与交付

1. 按需求建立页面配置，通过随包生成器生成高保真HTML。构建后自动执行静态检查，并尝试浏览器；同时输出页面同名`.validation.json`与`.validation.md`。浏览器可用时输出报告同名PNG截图。
2. 浏览器检查依赖宿主可用的Python Playwright与Chromium/Chrome；生成器仍只需Python标准库。不可用时标pending，不静默安装软件、不冒充渲染通过。若宿主有其他浏览器工具，可执行等价检查并单独保留证据。
3. 发现fail先读取规则与证据，回到需求、规范来源或组件绑定修复，然后重新生成复检。连续3次仍有同一失败时停下自动修改，交付明确标注的待修版本与阻塞说明；不得删除检查、重写期望值或绕过规范使报告变绿。局部修复不得扩大到未要求的业务改动。
4. 检查本次需求要求的全部交互：自动脚本目前只执行资金分类和AI展开，其余日期、筛选、搜索、排序、全屏、下钻及触屏场景需宿主逐项执行，并用单独人工/工具验证记录说明。不能借旧版测试记录证明新页通过。
5. 将生成截图与同数据、同状态、同尺寸的规范原件对照，检查页头、背景、图形几何、字体、图标、对齐、截断与间距。不存在可比原件时如实注明。不能用不同数据截图的像素差得出还原度百分比。
6. 修复后重跑；报告绑定HTML的SHA256，后续改HTML必须更新报告与截图。最终一起交付HTML与报告，标明失败/未验证及组件已知差异。旧截图或旧报告不能对应新文件冒充通过。

## 命令

```sh
python3 scripts/build_page.py --data 页面配置.json --out 页面.html
# 重新核查已生成文件；required在浏览器不可用时判失败
python3 scripts/validate_page.py --html 页面.html --browser required
# 若环境不能启动浏览器，仍执行静态核查，浏览器结果标为待验证
python3 scripts/validate_page.py --html 页面.html --browser off
```

可用`--browser-path`指定已安装Chrome/Chromium。生成器默认auto；只有校验发现fail才以非零退出。partial表示无已发现失败但存在待验证项目，不能描述为全部规范通过。

## 当前可自动验证的范围

| 规则 | 证据与边界 |
|---|---|
| 组件与资源复用 | 配置类型存在于组件注册表；内嵌CSS/JS与本包指纹及加载顺序一致；生成后样式、脚本及配置完整性；核心组件DOM与来源节点吻合。手写绘图贴同名标签不能代替资源检查。指纹证明使用本地实现，不证明实现与Figma逐像素相同 |
| 数据计算 | 资金T/C/V非负与范围，T=C+V+U，R=C+V，R/T及展示舍入；同级排名自身、邻位、脱敏、禁止下钻。其他指标公式需补专项断言，不能泛化为全部口径通过 |
| 浏览器运行 | 脚本/组件错误、实际外部请求（阻断）、375px整页溢出；允许排名内部横滑 |
| 测量槽位 | 详情摘要36/44、单位16/30、48%白层；排名金额14/22、名次16、表头32、行40。仅适用该规范组件，其他角色不能套用 |
| 字体 | 用Chrome实际渲染字体信息核查DIN/PingFang；仅声明CSS或document.fonts.check不算字形验证。字体缺失标pending并说明回退 |
| 图表与交互 | 资金DOM百分比、切分类总占比不变且选中状态更新；AI展开。其余交互保留待验记录 |

通用报告状态：fail（已发现错误）、partial（没有已发现错误，但有pending）、pass（本报告覆盖项均已验证）。全量视觉还原、业务选图判断及生产接口/权限不自动授予pass。报告始终保留全页视觉对照与未自动覆盖的交互提醒。

## 校验器自身验证

`python3 tests/test_page_validation.py`验证正常页面、错误资金余量、错误百分比、未知组件、样式篡改、无来源HTML六种情况。新增组件或规范更新时扩充测试；不得只检验报告有没有生成。
