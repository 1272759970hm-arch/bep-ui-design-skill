# 整页看板布局方法

> v1.3.0离线执行：来源链接/节点仅供追溯，常规生成不调用Figma。使用本地模板和证据，执行方式以[离线组件合同](offline-components.md)优先；原规范的样式/口径仍有效，缺口不得伪装为完整还原。


新页面或整页重构先按[UE分析](ue-analysis.md)确定用户任务、业务关系、信息架构与关键交互；本文件负责将这些决策落实到信息分组、页面规划表和空间预算。不要分别生成两套重复规划表，局部修正不强制扩展为整页重构。

本文件是依据项目整页观察和用户“根据整个页面布局”的要求形成的工作方法。具体高度、分组和布局选择为设计建议，不能称为原稿统一Token。先形成页面方案，再在同一方案中安排图表与UI。

## 1. 用业务问题组织页面

先确定这张页面用于概览、诊断、目标跟踪还是精确查询。按“当前表现→影响表现的因素→可查询明细/行动”构建阅读路径；原稿对不同业务有不同组合，不能把所有看板硬套相同环图卡。

建立信息地图，逐项记录：

| 字段 | 需要作出的决定 |
|---|---|
| 页面任务 | 看总览、看完成、查原因、比组织还是查合同 |
| 查询上下文 | 年/月/日、累计/单值、区域/项目及当前权限 |
| 主信息 | 哪个业务问题应最先被回答，金额与比率谁主谁辅 |
| 关联信息 | 支撑主信息的目标、变化、基数、构成、业务量 |
| 分析维度 | 是同时对比还是互斥Tab；各Tab需要什么数据 |
| 精确明细 | 分类行、排名、合同、单位及下钻对象 |
| 时效与解释 | 数据截至、延迟、锁数、释义和取数口径 |

每个原型字段有去向，避免视觉优化后把数值或业务限定词删掉。允许改变原型中的排布和分组；保留字段语义，不必复刻截图的留白和行高。

## 2. 用信息组决定卡片

**同组信息共同回答一个问题。** 比率与它的基数、完成情况与实际/目标、构成图与分类金额、趋势与时点读数应可在一个阅读单元中互相核对。不同任务、不同作用域或不同交互边界才需要另分模块。

同页可以同时使用主信息区、嵌入式小图、并列指标、行内条与明细表。卡片不是唯一的分组手段：共享底色、标题、对齐、分隔线和留白也能建立关系。采用项目既有风格，不为了变化引入无依据的装饰。

决定主次时按业务权重、读取频率和下一步操作分配空间。来源中大图并不意味本次必须大图：只有一个完成率且缺少其他分析数据时，可以让简洁进度表达与主值共同承担摘要，而不是让一个大环挤走订单与合同信息。反之，图表就是本页主要分析任务时，应给足读图空间。

## 3. 页面规划表

制作高保真前，用下表记录实际选择。简单任务用几行即可，避免写成冗长前置报告。

| 顺序/信息组 | 用户问题 | 内容及字段 | 主/辅助表达 | 首屏位置 | 切换/明细关系 |
|---|---|---|---|---|---|
| 查询上下文 | 现在看谁、看哪段时间 | 原型实际条件 | 紧凑控件和已选值 | 完整可见 | 全页作用域 |
| 经营摘要 | 当前表现如何 | 主金额、完成率、时间 | 主值＋适量图形＋参照 | 完整或核心完整 | 释义/分析入口 |
| 支撑业务 | 表现由什么支撑 | 同组相关指标 | 并列读数/小图 | 按优先级 | 同步口径 |
| 分析/明细 | 原因或行动在哪里 | 当前Tab所需字段 | 图、表或两者组合 | 完整/部分/滚动后 | 业务Tab/下钻 |
| 口径信息 | 这些数如何取得 | 更新时间与定义 | 弱说明/入口 | 按用途 | 只承诺真实存在的行为 |

实际顺序可以变化。不要先摆满若干同等卡片，再逐个往空白里填图。

## 4. 首屏预算

先扣除实际系统区域、必要导航与查询条件，再安排主要信息组。375×812只用于一轮参考检查：安全区按设备；没有底部Tab时不留Tab栏；原型是嵌入容器时不重复加系统栏。

记录每组的预估高度和位置，并区分“完整可见”“部分露出”“滚动后”。预估不是验收：真实字体、文案换行、控件尺寸和安全区加入后重新检查。数据变化需要扩大空间时，先调整分组、横向配合、显隐/展开及图形大小；不优先把所有文字缩小。

首屏应该让人理解本页主要结论和范围。页尾说明可在下方，但不能为了摆大图把关键业务模块完全隐藏且没有阅读线索；不能为了“一屏尽览”删字段或挤成不可读的小字。是否需要固定导航、固定筛选或折叠交互，按项目定义或本次明确建议处理。

## 5. 图形、数字与文字的分工

| 角色 | 任务 |
|---|---|
| 主数字 | 精确告诉用户“多少”；保留数值、符号、单位 |
| 图形 | 快速感知完成、差异、变化或构成，承担明确数据关系 |
| 参照 | 解释目标、上期、基数或比较对象 |
| 图例/标签 | 让颜色、形状与业务对象可对应 |
| 明细 | 支持精确查询、多字段、排名及下一步处理 |

合理重复可以帮助理解，例如摘要比率和分析图同值；重复必须有不同读取作用。多个独立完成率可以用统一尺度的小条或分组指标，也可选择主要环图加辅助读数；不能因为都带百分号就各放一个同样大的环。金额之间的业务关系未确认时，不计算其构成份额。

## 6. 当前经营收入原型的应用示例

这是一种可供试排的整页方案，不是已经完成的新UI，也不锁定最终图形。这些字段只适用于本次完整来源原型；新任务只提供部分字段时不得从本例补齐日期、T+1、Tab或业务数据。

| 信息组 | 原型字段去向 | 建议职责 |
|---|---|---|
| 上下文 | 2026年、年度/月度、区域/项目、全国 | 保留不同选择维度的层级，控制区避免与数据区争主位 |
| 收入摘要 | 区域累计8726.4万元、87.26%、截至8月累计、T+1、数据截至8月30日 | 同组表达金额与完成；可从数值＋紧凑进度试排，若选环则共同规划横向空间和字号 |
| 支撑指标组 | 提效性2386.4万元与91.8%；新增订单1064.8万元与318单 | 各自相关值成对，次级层级；可与摘要共享主容器，不必拆成三四张独立卡 |
| 业务分析/合同 | 收入构成、经营效率、合同情况；124.6万元、38个、61笔 | 保留当前合同Tab精确列表和名称；不能拿三个不同单位值拼图 |
| 口径 | 年度累计/月度查询月、取数口径入口 | 解释与时效保留，Demo/复用H5等移为设计注释 |

该页没有时间序列与收入分类数据，不能捏造趋势或构成。缺少目标和分子分母时，只显示已给出的比率并标出业务缺口，不能倒算目标后当成原型事实。

参考首屏试排可将导航/系统/查询共约220–250、经营摘要与支撑组约280–340，余下空间给业务Tab及部分合同明细；这些数字仅说明需要预算，并非固定尺寸。执行时可选择不同组合。未渲染时报告预估与待验证条件；完成渲染后再报告实际折叠线位置和长页高度。

## 7. 按整页验收

逐项检查：核心问题是否先得到回答；主次是否明确；同组信息是否相邻；图表是否提供了额外信息；筛选/维度/口径是否分清；原型字段是否有去向；图例/数值/明细是否一致；首屏是否可读；滚动后模块是否可达；真实字体与长标签是否破坏布局。

最后再检查色值、字号、环厚、线宽等局部参数。局部都符合规范不能单独证明整页效果合格。
