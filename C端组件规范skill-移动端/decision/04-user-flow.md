# 04 · User Flow (用户任务流分析)

> Skill 强制流程 Step 4。
>
> **确保页面不是信息堆砌，而是围绕用户任务设计**。

---

## 6-Step Flow 模板（强制填完）

```
1. Entry     用户从哪里进入？（触点 / 上下文 / 心理状态）
2. See       用户第一眼看到什么？（顶屏内容 / 视觉焦点）
3. Understand 用户如何理解页面？（信息组织 / 视觉引导）
4. Act       用户做什么核心操作？（主 CTA / 次操作）
5. Feedback  操作后得到什么反馈？（视觉 / 音效 / 跳转）
6. Next      下一步去哪里？（延续任务 / 完成 / 探索）
```

**规则**：每一步都要能一句话回答。**任何一步说不清 = UX 断链，返回 Step 1**。

---

## 示例：商品详情页 User Flow

```
1. Entry:      从搜索结果 / 推荐进入，处于比价决策阶段
2. See:        顶屏看到主图 + 价格（决定"感兴趣程度"）
3. Understand: 下滑看规格、优惠、评价（建立"信任"）
4. Act:        点击"立即购买"（sticky 底部）
5. Feedback:   跳转到选规格弹窗 / 直接进入结算
6. Next:       结算成功 → 支付页；犹豫 → 加购收藏 → 继续比较
```

---

## 示例：物业报事页 User Flow

```
1. Entry:      家里发现问题（漏水/异响），从 App 首页进入
2. See:        顶屏看到"公共区域报修"标题 + 我要投诉/找管家/公共区域报修 三个入口
3. Understand: 明白只需要选类型、描述、传图三步
4. Act:        选类型 → 输入描述 → 拍图 → 提交
5. Feedback:   提交成功 toast + 工单号 + 预计响应时间
6. Next:       返回列表看已提交工单 / 继续报修其他问题
```

---

## 示例：支付成功页 User Flow

```
1. Entry:      从支付页付款成功回调进入，情绪放松
2. See:        大绿勾图标 + "支付成功"
3. Understand: 一眼确认订单已完成，无需焦虑
4. Act:        点击"查看订单"（主 CTA）或"返回首页"（次 CTA）
5. Feedback:   跳转对应页面
6. Next:       订单页看物流 / 首页继续购物
```

## 认知负担检查清单（每页必查）

- [ ] 用户能在 **3 秒内**说出"这个页面是干什么的"吗？
- [ ] 主 CTA 是否在**无需思考的位置**？（sticky 底部 / 视觉终点）
- [ ] 是否存在 **2 个以上竞争性主 CTA**？（有 = 违规，用户会犹豫）
- [ ] 页面首屏是否包含**完成核心任务的全部关键信息**？
- [ ] 折叠的信息（如"查看更多"）是否**真的次要**？（不是把核心信息藏起来）
- [ ] 用户完成 Task 需要多少步？（**>3 步 = 流程需优化**）
- [ ] 是否有任何元素让用户思考"这是什么意思"？（有 = 简化文案 / 加提示）
- [ ] 用户在完成任务过程中，**是否会突然遇到需要跳出页面**的情况？（避免流程中断）

## 常见 Flow 反模式

### 反模式 1：Flow 断链

**症状**：Step 6（Next）说不清"用户完成后去哪里"。

**举例**：报事提交成功后，只有 toast，没告诉用户"去哪儿看工单进度"。

**修法**：Step 6 必须明确指向具体页面 / 动作。

---

### 反模式 2：主 CTA 竞争

**症状**：多个视觉重量相同的按钮，用户不知道点哪个。

**举例**：详情页底部同时有"分享"、"收藏"、"加购"、"立即购买"四个大按钮。

**修法**：主 CTA 只允许 1 个（强色/大尺寸），其他降级为图标或次要按钮。

---

### 反模式 3：See ≠ Task

**症状**：用户第一眼看到的不是任务相关信息。

**举例**：订单详情页顶部放"推荐商品"，"当前订单状态"要滑动才能看到。

**修法**：顶屏必须服务 Task。

---

### 反模式 4：Understand 靠说明

**症状**：页面靠大量文字说明才能理解怎么用。

**举例**：卡片顶部有一段"请先选择服务类型再填写问题描述..." 说明。

**修法**：信息结构应自解释，不靠说明。说明只用于"用户可能困惑的边缘操作"。

---

### 反模式 5：无 Feedback

**症状**：用户操作后不知道成功了没。

**举例**：点击提交按钮后无 toast、无跳转，页面看起来没变化。

**修法**：任何操作必须有反馈（toast / 页面变化 / 跳转）。

## User Flow Card 模板（Step 4 的产物）

```
## User Flow Card

1. Entry:      [用户从哪来 + 情绪状态]
2. See:        [顶屏看到什么 = 视觉焦点]
3. Understand: [如何理解 = 信息组织]
4. Act:        [主操作 = P0 CTA]
5. Feedback:   [操作后的反馈]
6. Next:       [下一步去哪]

认知负担: [清单检查结果]
主 CTA 唯一性: [是 / 否]
Flow 完整性: [完整 / 有断点 (说明在哪一步)]
```

## AI 检查清单（Step 4 完成后自查）

- [ ] 6 步全部有一句话答案？
- [ ] 主 CTA 只有 1 个？
- [ ] 顶屏内容与 Task 直接相关？
- [ ] 认知负担清单全部通过？
- [ ] Step 6 (Next) 有明确去向？

任何一项 fail → 修改 Flow 或回 Step 3 调整 IA。

---

## 与后续步骤的衔接

- **See → Step 5 视觉焦点**：See 内容决定视觉焦点位置
- **Act (主 CTA) → Step 5 CTA 设计**：CTA 视觉规格
- **Feedback → Step 7 组件选择**：可能需要 Toast / Dialog 组件
- **Next → 后续页面设计**：多页流程时衔接下一页
