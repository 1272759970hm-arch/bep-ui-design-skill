# 设计校验（交付前八维自检）

> 本文件是**设计层**的交付前校验：产品逻辑、IA、交互、页面完整性、组件、状态、视觉、PC 体验。
> **代码层**校验由 `scripts/tools/validate-page.js` 负责（组件替身、图标、列宽审计、状态参数、铁律）。两者分工不重叠：脚本查代码，本文件查设计。

---

## 执行顺序（不可颠倒）

```
产品逻辑 → 信息架构 → 交互 → 页面完整性 → 组件使用 → 状态完整性 → 视觉层级 → PC 体验
```

先做层级高的判断：产品逻辑不成立时，视觉再规范也是废页。每维检查完再进入下一维。

---

## 级别定义

| 级别 | 含义 | 交付要求 |
|---|---|---|
| **阻塞** | 不修不能交付（业务错误、任务断点、必然出错） | 必须修复；确实无法修复时必须在交付说明中列为已知问题并给出影响范围 |
| **建议** | 可以交付，但应尽快改 | 记入交付说明的「建议改进」 |

**禁止**把阻塞项降级为建议项混过去；也禁止把纯风格偏好标成阻塞。

---

## 一、产品逻辑

| 检查项 | 不合格表现 | 级别 |
|---|---|---|
| 业务规则计算/口径正确 | 金额、税额、余额、累计值算不出来或口径不清 | 阻塞 |
| 状态流转闭合 | 出现无法到达或无法退出的状态 | 阻塞 |
| 主操作符合业务规则 | 状态不允许时仍可操作（如审批中仍可编辑） | 阻塞 |
| 数据来源正确 | 只读主数据出现可编辑入口 | 阻塞 |
| 权限一致 | 不该看到的数据/操作出现了 | 阻塞 |
| 无自相矛盾的规则 | 提示文案与校验规则相反 | 阻塞 |
| 指标定义明确 | 看板指标无口径说明 | 建议 |

---

## 二、信息架构

| 检查项 | 不合格表现 | 级别 |
|---|---|---|
| 每页有明确用户任务 | 说不出这页解决什么 | 阻塞 |
| 一页一主任务 | 一页里塞了三件不相干的事 | 阻塞 |
| 入口唯一 | 同一功能出现多个正主入口 | 阻塞 |
| 层级单向可回溯 | 出现 A→B→C→A 环路，或只能靠重置返回 | 阻塞 |
| 分组性质一致 | 作业类与配置类平铺同层 | 建议 |
| 低频不占一级 | 一次性工具占一级导航 | 建议 |
| 命名与业务一致 | 页面名/菜单名不表达业务对象 | 建议 |
| 不为展示组件造页面 | 存在无业务任务的页面 | 阻塞 |

---

## 三、交互逻辑

| 检查项 | 不合格表现 | 级别 |
|---|---|---|
| 主路径完整 | 缺入口或缺出口 | 阻塞 |
| 形态选择合理 | 复杂表单用弹窗、轻量确认用通用弹窗 | 建议 |
| 弹层层级 ≤2 | 弹窗套弹窗套弹窗 | 阻塞 |
| 危险操作有二次确认 | 删除/作废无需确认 | 阻塞 |
| 无冗余确认 | 普通操作也弹确认 | 建议 |
| 提交防重复 | 提交按钮无 loading、可连点 | 阻塞 |
| 批量可全选、显示条数 | 无全选或已选数不可见 | 建议 |
| 反馈明确 | 操作后无任何提示或状态无变化 | 阻塞 |
| 离开拦截 | 表单有内容时直接关闭丢失 | 建议 |
| 返回保留上下文 | 返回后筛选/位置丢失 | 建议 |

---

## 四、页面完整性

| 检查项 | 不合格表现 | 级别 |
|---|---|---|
| 骨架模块齐全 | 列表页缺筛选、缺分页、缺行入口 | 阻塞 |
| 字段完整 | 原型/需求中明确要求的字段缺失 | 阻塞 |
| 字段位置合理 | 操作列被挤到需横向滚动才可见 | 建议 |
| 分组按亲近关系 | 弱相关信息塞进同一卡片 | 建议 |
| 动态记录归属正确 | 操作记录混入静态信息描述列表 | 阻塞 |
| 无多余内容 | 出现需求未要求且无业务依据的模块 | 建议 |
| 大数据量有策略 | 10 万级数据无分页/无筛选 | 阻塞 |

---

## 五、组件使用

| 检查项 | 不合格表现 | 级别 |
|---|---|---|
| 只用标准组件 | 页面内出现自造组件替身 | 阻塞 |
| 组件选型正确 | 该用描述列表的地方用表格拼 | 建议 |
| 组件入口正确 | 绕过公开入口拼内部结构 | 阻塞 |
| 图标来自 BeP 图标库 | 手绘图标或注入图标集 | 阻塞 |
| 表格按列建模 + 列宽审计 | 缺 `COL_WIDTH_AUDIT` | 阻塞 |
| 操作列宽来自计算 | 手写估算列宽 | 阻塞 |
| 缺口按流程处理 | 缺组件就自己写一个近似品 | 阻塞 |

> 以上均会被 `validate-page.js` 强制检查；本维只需确认无 warning 遗留、且已按流程补齐缺口。

---

## 六、状态完整性

按 `interaction-design.md` §二 矩阵逐页核对。

| 检查项 | 不合格表现 | 级别 |
|---|---|---|
| 空态 | 无数据时白屏 | 阻塞 |
| 加载态 | 无 loading 表现 | 建议 |
| 失败态 + 重试 | 失败无提示或无重试 | 阻塞 |
| 无权限态 | 无权限时白屏或 404 文案 | 阻塞 |
| 禁用态原因 | 禁用但不说原因 | 建议 |
| 校验失败定位 | 只标红不定位、不给清单 | 建议 |
| 部分成功 | 批量后只报「完成」 | 建议 |
| 只读态 | 详情页出现编辑态样式（输入框、校验红边） | 阻塞 |

---

## 七、视觉层级

| 检查项 | 不合格表现 | 级别 |
|---|---|---|
| 文字层级 ≤3 | 出现四种以上字号 | 建议 |
| 颜色语义正确 | 主色用于危险操作、红色用于提交 | 阻塞 |
| 数值右对齐 + 千分位 | 金额左对齐、无千分位 | 建议 |
| 唯一标识不截断 | 编号被省略号截断 | 阻塞 |
| 页面级卡片无阴影 | 到处加 `effects` 阴影 | 建议 |
| 语义不靠颜色单独表达 | 只用红/绿表示状态无文字 | 建议 |
| 描述列表铺满宽度 | 右侧大片空白 | 建议 |

---

## 八、PC 端体验

按 `pc-ux-principles.md` §十 自检；重点关注：

| 检查项 | 不合格表现 | 级别 |
|---|---|---|
| 首屏可完成主路径 | 主按钮需滚动才能看到 | 阻塞 |
| 密度达标 | 折叠态表格 <10 行、单模块占满一屏 | 建议 |
| 正文字号不低于 14 | 为塞内容把正文压到 12 | 建议 |
| 操作距离合理 | 主操作与操作对象隔屏 | 建议 |
| 返回保留上下文 | — | 建议 |
| 大数据策略明确 | — | 阻塞 |

## 九、交付说明模板

交付时必须包含以下五段（简单需求的 2、3 段可合并）：

```md
## 交付说明 · <页面/模块>

### 1. 结论
- 生成文件：`pages/<模块>/<页面>.js`；构建产物：`pages/<模块>/dist/<页面>.js`
- 页面类型：<类型>；模板：<模板编号>
- 校验结果：`build` 通过 / `validate-page` 通过（warning N 项，说明如下）

### 2. 设计决策
| 决策点 | 选择 | 理由 |
|---|---|---|

### 3. 信息架构与页面结构
- 页面在结构中的位置 / 来路 / 去路
- 骨架顺序与关键模块

### 4. 交互与状态
- 状态覆盖：空 / 加载 / 失败 / 无权限 / 校验 / 重复提交
- 异常处理与反馈方式

### 5. 风险与待确认
- 示例数据（如有）标注
- 组件/图标缺口与候选方案
- 阻塞项或已知问题及影响范围
- 建议改进项
```

## 十、常见返工原因（Top 8）

| # | 原因 | 预防 |
|---|---|---|
| 1 | 只做 happy path | 先过 §六 状态矩阵 |
| 2 | 字段超 8 汉字未简化 | 生成前先扫字段名（`form-rules.md`） |
| 3 | 表格列宽手写估算 | 必须输出 `COL_WIDTH_AUDIT` |
| 4 | 详情页照搬编辑页分区 | 按查看语义重组 |
| 5 | 入口重复、用户不知走哪个 | 先过 §二 IA |
| 6 | 弹窗承载过重表单 | 按 `interaction-design.md` §4.2 判据选形态 |
| 7 | 组件缺口自行造 | 提缺口、按流程补组件 |
| 8 | 为还原原型牺牲任务闭环 | 优先级 P1 > P5 |
