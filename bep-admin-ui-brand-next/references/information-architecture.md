# 信息架构（IA）

> 本文件规定 PC 后台系统的模块划分、导航层级、页面清单与页面关系。
> 目标：页面由**业务对象和用户任务**推导，而不是由「有哪些组件可以用」推导。

---

## 适用时机

满足任一即必须先做 IA，再进入页面结构：

- 新建模块 / 新建系统
- 页面 ≥3 个，或需要判断「该拆几个页面」
- 导航调整（一级/二级菜单增删、入口合并、层级下放）
- 需求出现「一个页面里要放好几件事」

---

## 一、判断顺序（不可颠倒）

```
业务对象 → 生命周期阶段 → 用户任务与频率 → 模块划分 → 页面清单 → 导航落位 → 页面关系
```

1. **业务对象**：系统管的是什么（合同 / 项目 / 客户 / 订单 / 供应商…）。对象是模块划分的第一依据。
2. **生命周期阶段**：对象的阶段（创建 → 变更 → 执行 → 结算 → 关闭）。阶段是**二级模块**的常见依据。
3. **用户任务与频率**：同一对象下，按任务拆（录入 / 查询 / 批量作业 / 配置）；频率决定排序与升降级。
4. **模块划分**：见 §二。
5. **页面清单**：每个模块下有哪些页面，每页解决一个任务（见 §三）。
6. **导航落位**：哪些进一级、哪些进二级、哪些降级为页签或「更多」（见 §四）。
7. **页面关系**：来路、去路、跨模块跳转（见 §五）。

---

## 二、模块划分判据

### 分组原则

按**使用频率 + 数据性质**分组，从高频作业到低频配置自上而下排列：

| 组 | 性质 | 典型内容 | 位置 |
|---|---|---|---|
| 工作台 | 用户每天第一眼 | 待办、消息、快捷入口、公告 | 一级，置顶 |
| 业务作业 | 高频、写操作、有流程 | 录入、批量处理、审批 | 一级，靠上 |
| 查询与报表 | 中低频、只读 | 台账、查询、导出 | 一级，居中 |
| 初始化 / 工具 | 一次性或偶发 | 期初、导入、数据修复 | 二级或「更多」，可折叠 |
| 基础数据 / 配置 | 低频、管理员为主 | 主数据、字典、组织、权限 | 一级，置底，可按角色隐藏 |

### 硬性规则

- **同一层不混性质**：作业类、查询类、配置类不得平铺在同一层（否则用户无法建立认知地图）。
- **主数据与业务数据分开**：外部同步的只读主数据（来自 MDG/ERP 等）不与可编辑业务配置混在一个二级组；只读的用「查看」语义，不出现「新增」。
- **配置归属看影响范围**：只影响本业务域的配置留在业务域下（如「合同业务类型」）；跨域共用的配置进「基础数据」。
- **模块数上限**：一级 3–7 个，二级每组 ≤7 个，三级尽量不出现（改用页签 / 页内分组 / 折叠）。

## 三、页面清单格式

输出必须同时给**树**和**表**：树看层级，表看每页做什么。

### 树

```
系统名
├─ 工作台
│  ├─ 数据总览
│  ├─ 待办事项
│  └─ 业务预警
├─ 项目管理
│  ├─ 项目列表
│  ├─ 项目详情
│  └─ 项目跟进
├─ 客户管理
│  ├─ 客户列表
│  └─ 客户详情
└─ 数据分析
   ├─ 业务分析
   └─ 项目分析
```

### 表

| 页面 | 类型 | 用户任务 | 主操作 | 入口 | 出口 | 频率 |
|---|---|---|---|---|---|---|
| 项目列表 | 列表页 | 找项目、看进展、批量跟进 | 新建项目 | 菜单 / 工作台待办 | 项目详情 | 每天 |
| 项目详情 | 详情页 | 核对全部信息、执行动作 | 编辑 / 跟进 | 列表行、全局搜索 | 返回列表 | 每天 |

**要求**：

- 每页必须写出「用户任务」；写不出来的页面**不要建**。
- 「频率」列用于排序与升级/降级判断，不确定就写推断依据（如「按业务节奏推断：月度」）。
- 一个页面只承担一个主任务；出现第二个主任务 → 拆页或改用页签。

## 四、导航落位与层级规则

### 一级导航

- 只放**模块**，不放功能点、不放系统名、不放「更多」。
- 一级必须能用一句话说清「这里面是干什么的」。
- 一级数量 3–7；超出说明模块划分过细，应合并。

### 二级导航

- 二级是**模块内的功能分组或页面**，≤7 个。
- 二级支持折叠；默认展开当前所在组，其余收起（减少视觉噪音）。
- 需要「多一层但不够一个二级」时，优先用：页内页签（`bepCardTabs`）> 页内分组 > 折叠面板。

### 降级与收起的判据

| 情形 | 做法 |
|---|---|
| 低频（月度以下且非关键） | 收进「更多 ▾」或作为二级折叠组的子项 |
| 一次性（初始化、数据迁移） | 完成期后收起，交付说明中标注「可下线」 |
| 仅管理员使用 | 按角色隐藏整组（见 `design-process.md` §三 权限表现） |
| 与既有页面是同一任务的不同视角 | 合并为页签或筛选视图，不新增菜单 |

### 顶部与侧边的分工

- **顶部（全局件）**：品牌、全局搜索、快捷（收藏 / 最近使用）、消息、待办、语言、个人中心。不承载业务入口。
- **侧边（业务导航）**：模块与页面入口。
- **禁止导航复述**：顶部出现「功能菜单」这类把侧边导航再列一遍的入口 → 删除。重复入口会让用户不知道以哪个为准。
- **系统打开机制二选一**：`TopBar + Breadcrumb`（下钻）或 `TopBar + PageTabs`（多任务工作台），同一系统内不得混用（沿用 `SKILL.md` 页头系统模式规则）。
- 侧边栏实现使用 `bepSidebarLogo` / `bepSidebarItem(label, level, state, iconKey)`；层级用 level 1/2/3，不靠缩进视觉硬凑。

## 五、页面关系（来路 / 去路 / 跨模块）

### 三类关系必须显式设计

| 关系 | 说明 | 落地方式 |
|---|---|---|
| 层级关系 | 列表 → 详情 → 子详情 | 面包屑表达路径；下钻不丢当前页 |
| 平级关系 | 同对象的多个视角（台账 / 报表 / 日志） | 页签或模块内二级；不得互相跳来跳去形成环路 |
| 对象关系 | 单据 ↔ 所属对象（合同 ↔ 计提/付款单） | 双向链接：单据页给「返回所属对象」，对象页可下钻到单据 |

### 对象型入口 vs 单据型入口

后台系统常见「用户记不住东西在哪个节点」问题，根因是**导航按单据类型组织，而用户脑子里装的是业务对象**。处理原则：

1. **对象型任务**（不知道在哪个节点）→ 需要**以对象为行**的台账 / 概览页 + 全局搜索（结果按对象与单据分组）+ 全站对象编号可点（编号即链接）。
2. **单据型任务**（知道节点、要批量作业）→ 保留按单据类型组织的作业页签。
3. 两者并存，互相不替代；共同落点是一个**对象全景页**（顶部关键数值汇总 + 按节点分组的单据 + 生命周期时间轴）。

### 主路径必须闭合

每个页面都要能回答：从哪进来、办完去哪、能不能回来。出现「只能靠重置页面回到」即视为断点，必须补。

## 六、内容优先级与操作入口

- **首屏必须回答的问题 ≤3 个**（如「有多少、有什么异常、我该做什么」），其余信息下沉到次级区域或页签。
- 信息分组按**业务亲近关系**：同一对象、同一阶段、同一查看任务 → 同组；明细 / 日志 / 附件 → 独立分组。
- **主操作唯一**：每页一个主按钮（`bepButton` type=primary），其余为次要或收进「更多」。动词统一：新建 / 发起 / 导入 / 导出，同一动作全系统同一动词。
- **工具栏布局**：批量操作靠左，主按钮靠右（沿用 `filter-rules.md` 与既有列表页规则）。
- 高频操作必须能在一屏内触达，不需要滚动或展开。

---

## 七、禁止事项

- **不为展示组件造页面**：某个组件很好看就给它配一个页面 → 禁止。页面必须由业务任务推导。
- **不因模板存在就加页面**：模板是结构参考，不是页面清单来源。
- **不做导航复述**：不出现与侧边导航重复的菜单页 / 菜单树页面。
- **不给低频配置占一级导航**。
- **不把同一功能放在多处**（顶部、首页、二级菜单各一份）——同一功能只保留一个正主，其余做快捷入口并指向它。
- **不按部门名划分模块**（部门会变，业务对象不会）。
- **不做环形跳转**（A → B → C → A），层级关系必须单向可回溯。

## 八、常见问题与处理（来自真实系统复盘）

| 现象 | 根因 | 处理 |
|---|---|---|
| 待办 / 已办在顶部、首页、工作台三处出现 | 快捷入口当成了功能实现 | 保留一处正主（工作台），其余为指向它的入口 |
| 「消息通知」与「消息中心」并存 | 点名与功能重名 | 区分语义：点对点消息 vs 系统公告，各留一个 |
| 「基础数据」与「业务建模」边界说不清 | 两者都是「配置/主数据」 | 合并为一组，内部再分「主数据 / 业务配置」 |
| 顶部「功能菜单」把侧边导航再列一遍 | 历史遗留 | 删除 |
| 报表类 7 项平铺无主次 | 缺少二级分组 | 主入口（台账/查询）+ 「专项台账 ▾」 |
| 菜单里出现「更多」但展开后只有 1 项 | 降级过度 | 该项回到二级 |
| 初始化类菜单长期占位 | 阶段结束未收起 | 收起或下线，交付说明标注 |

```md
| 一级 | 二级 | 性质 | 依据（对象/阶段/频率） |

### 2. 页面清单
（见 §三 表）

### 3. 导航落位
- 一级：…
- 二级：…
- 降级 / 收起：…（原因）
- 按角色隐藏：…

### 4. 页面关系
| 从 | 到 | 触发 | 返回方式 |

### 5. 待确认
- 合并 / 删除 / 升降级的建议与依据
```
