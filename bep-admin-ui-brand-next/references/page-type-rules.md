# 页面类型判断与结构骨架

> 本文件规定「怎么判断页面属于哪一类」以及「该类页面的结构顺序」。
> `page-templates.md` 负责落地（用哪些组件、间距多少、列宽怎么算）；本文件负责**判断与骨架**。

---

## 使用方式

1. 读需求 → 对照 §一 识别信号定类型（每页只允许一个主类型）。
2. 用 §二 对应小节拿到**结构骨架顺序**（自上而下的模块顺序）。
3. 用 §三 映射到 `page-templates.md` 的模板编号。
4. 用 §四 检查是否落入常见误用。

骨架只规定**顺序与必备模块**，不规定组件细节；组件细节以 `page-templates.md` 与组件文档为准。

## 一、十二类页面识别信号

| 类型 | 识别信号（需求里出现） | 主任务 | 判据要点 |
|---|---|---|---|
| 工作台 / 首页 | 「首页」「总览」「我的一天」「概览」 | 快速掌握状态并进入下一步 | 首屏回答「有多少 / 什么异常 / 我该做什么」 |
| 列表页 | 「列表」「管理」「查询列表」「台账」 | 在大量记录中定位并批量处理 | 有筛选 + 表格 + 分页 + 行操作 |
| 搜索 / 查询结果页 | 「搜索」「查一下」「查单据」 | 已知线索精确找到目标 | 搜索框为主，结果需分组（对象 / 单据） |
| 详情页 | 「详情」「查看」「信息」「全景」 | 核对完整信息并执行动作 | 只读为主，分组描述，动态记录独立 |
| 表单页 | 「新增」「编辑」「填写」「发起」 | 录入 / 修改并提交 | 字段分组 + 校验 + 提交去向 |
| 多步骤流程 | 「向导」「分步」「流程」「N 步」 | 完成复杂录入 | 每步一件事、字段 ≤8、可暂存可回退 |
| 数据看板 | 「看板」「Dashboard」「分析」「报表图」 | 观察趋势与对比 | 指标 + 图表为主，非操作型 |
| 配置页 | 「配置」「设置」「字典」「类型」「模板」 | 定义规则与字典 | 层级 + 启停 + 影响范围说明 |
| 审批页 | 「审批」「待审」「流程处理」 | 判断并做出同意/驳回 | 上下文 + 意见 + 下一步流转 |
| 内容管理页 | 「文章」「公告」「内容」「素材」 | 维护发布内容 | 编辑器 / 状态（草稿-发布-下线） |
| 弹窗 / 抽屉 | 「弹窗」「抽屉」「弹一下」「侧滑」 | 局部处理，不离开当前上下文 | 表单复杂度低、需保留上下文 |
| 空状态 / 异常状态 | 「没数据」「失败」「无权限」 | 说明情况并给出口 | 不是独立页面，是每页的必备状态 |

**同名不同类警告**：都叫「列表」但语义不同——

- **业务单据列表**：可新建、可批量、有状态流转 → 典型列表页
- **只读主数据列表**：数据来自外部同步，只有「查看」→ 应按「查询页 + 只读」设计，不出现「新增/删除」
- **配置项列表**：行内可编辑启停 → 按配置页设计，主操作是「保存」而不是「新建」

## 二、结构骨架（自上而下顺序）

### 1. 工作台 / 首页

```
页头（标题 + 说明）
→ 快捷入口 / 常用功能（收藏）
→ 待办 / 预警（首屏最需要行动的内容，优先于统计）
→ 核心指标摘要（3–5 个，指标数据卡片）
→ 次要信息（公告、动态）
```

- 必答：用户每天来这里最想立刻看到什么？答不出先别做。
- 禁止：图表墙、把统计放在待办之前、把工作台做成数据看板。

### 2. 列表页

```
页面标题
→ 页面说明（一句话，可选，仅在业务规则复杂时）
→ 筛选区（≤5 条一行 + 展开更多 / 或三列网格折叠）
→ 状态快捷条（多状态业务必备，单行 + 计数）
→ 操作区（批量靠左，唯一主按钮靠右）
→ 数据表格（固定列序、数值右对齐、表尾合计）
→ 分页（总数 + 每页条数 + 跳页）
→ 行内入口（查看 / 详情，作为操作列）
```

- 必答：数据量级（决定分页方式与是否需要保存视图）、是否需要批量、空态文案。
- 列序规则：标识列 → 名称列 → 业务属性 → 金额/数值 → 状态 → 时间 → 操作。
- 禁止：先摆组件再想结构；把状态筛选做成下拉而不用可见的快捷条（高频状态值得常驻）。

### 3. 搜索 / 查询结果页

```
搜索框（置顶、聚焦、支持编号/名称/供应商等）
→ 结果分组（对象组 / 单据组，各带条数与来源说明）
→ 每组结果列表（带上下文：所属对象、共 N 张单据）
```

- 必答：用户记的是什么（编号 / 名称 / 供应商 / 项目）→ 决定可搜字段。
- 禁止：只给一个平铺结果列表，不带上下文。

### 4. 详情页

```
页头（标题 + 面包屑或页签）
→ 对象标题摘要（页头标题型，含状态与标签）
→ 关键数值汇总（3–5 个）
→ 描述分组（亲近关系强 → 同一 Card 多 sections；弱 → 独立 Card）
→ 明细表格 / 附件（独立分组）
→ 动态记录（时间轴，独立页签或分组）
```

- 必答：概览放哪几个字段、动态记录放哪、可执行动作是什么、返回去哪。
- 禁止：机械照搬编辑页锚点分区；把操作记录塞进静态信息描述列表。

### 5. 表单页

```
页头
→ 系统字段摘要条（编号 / 状态等，只读，可复制）
→ 分组（每组一个业务主题，组内两列）
→ 必填与校验提示（统一 *，与校验同源）
→ 附件 / 正文（独立分组）
→ 底部操作（返回 + 暂存/取消 + 提交）
```

- 必答：哪些必填、能否暂存、离开是否拦截、提交后去哪。
- 字段上限：单页 ≤20 个；超过 → 拆步骤（见 6）。
- 禁止：字段标题超 8 汉字不简化（执行铁律）；把系统生成字段做成可输入框。

### 6. 多步骤流程

```
步骤条（贯穿，已完成步骤可点回退）
→ 每步标题 + 说明
→ 当前步内容（字段 ≤8，一件事）
→ 步骤内上下文（如当前所选规则摘要，常驻侧栏）
→ 底部：退出 / 暂存 / 上一步 / 下一步（末步为提交）
→ 确认步（分组回显 + 每组「修改」精确回跳）
→ 完成态（结果编号 + 状态 + 去向）
```

- 拆步判据：一屏装不下的「三块业务主题」必须拆；拆完必须配**自由跳转 + 前置校验拦截**，否则只是把点击变多。
- 补偿机制（拆步必备，至少两条）：步骤条任意步可点、可跳过非必填步、进度提示（必填已完成 n/m）、当前选择摘要常驻。
- 禁止：无步骤条的分步表单；确认页写死回显；完成后无反馈。

### 7. 数据看板

```
页头（标题 + 时间范围切换）
→ 指标摘要区（指标数据卡片，3–6 个）
→ 图表区（图表容器，按「趋势优先、对比次之、分布再次」排序）
→ 明细/排行模块（看板表格、排行榜）
```

- 必答：指标口径、时间范围、下钻路径、空数据表现。
- 禁止：用指标卡代替图表；图表无口径说明；C 端式大留白。

### 8. 配置页

```
页头
→ 层级导航（树，如左树右表）或分组页签
→ 列表 / 表单区
→ 影响范围与生效说明（写清楚改了会影响谁）
→ 保存 / 启用停用
```

- 必答：层级深度、是否影响历史数据、启停语义、谁有权改。
- 禁止：把配置页做成业务列表页（出现「批量删除」这类业务动作）。

### 9. 审批页

```
单据摘要（关键字段，一眼判断）
→ 审批上下文（附件 / 明细 / 历史意见，时间轴）
→ 审批动作区（同意 / 驳回 / 转办；意见必填规则）
→ 流程信息（当前节点、上一节点、下一节点）
```

- 必答：通过/驳回后流转到哪、能否撤回、能否批量审批、超时如何处理。
- 禁止：把审批页做成纯详情页而不给动作区。

### 10. 内容管理页

```
列表（状态：草稿 / 已发布 / 已下线）
→ 编辑器（富文本或结构化）
→ 发布设置（范围、时间、置顶）
→ 状态与操作（发布 / 下线 / 撤回）
```

- 必答：发布范围、生效时间、可否撤回、谁可见。

### 11. 弹窗 / 抽屉

```
标题（说清做什么）
→ 内容（表单 ≤1 列 / 或只读描述）
→ 底部操作（取消 + 确认；仅表单型有）
```

- 规格：弹窗 420/640/800，抽屉 420/640/800；内容宽度 = 容器宽 −48。
- 禁止：弹窗套弹窗超过 2 层；用弹窗承载需要上下文的复杂表单（应改抽屉或页面）。

### 12. 空状态 / 异常状态

不是独立页面，是**每页必备**的结构部分：

```
空状态（`bepEmptyState`）：一句话说明 + 主操作（若有）
加载：骨架或 loading（禁止空白）
失败：原因 + 重试
无权限：说明 + 申请入口
部分失败：成功 N 条 / 失败 M 条 + 失败明细与重试
```

## 三、类型 → 模板映射

| 页面类型 | `page-templates.md` 模板 |
|---|---|
| 工作台 / 首页 | ⑩ 数据看板（指标 + 模块平铺）+ ① 列表（待办） |
| 列表页 | ① 基础表格 / ② 三列筛选展开收起 / ③ 页签表格 |
| 搜索 / 查询结果页 | ① 基础表格（去掉重筛选）+ 结果分组 |
| 详情页 | ③b 详情页（卡片内页签） |
| 表单页 | ⑤ 基础表单 |
| 多步骤流程 | ⑥ 分步表单 |
| 数据看板 | ⑩ 数据看板 |
| 配置页 | ④ 树表格 / ④b 高级表格 / ⑤ 基础表单（配置表单） |
| 审批页 | ③b 详情页 + 动作区 |
| 内容管理页 | ① 基础表格 + ⑤ 基础表单 |
| 弹窗 / 抽屉 | ⑦ 弹窗 / ⑧ 抽屉 |
| 空状态 / 异常状态 | 组件：`bepEmptyState` + `bepAlert` |

## 四、常见误用

| 误用 | 后果 | 纠正 |
|---|---|---|
| 看到「列表页」就机械调组件 | 结构对了但任务不闭环 | 按 §二·2 骨架逐项核对 |
| 工作台做成看板 | 首屏没有行动入口 | 待办/预警前置 |
| 详情页照搬编辑页分区 | 字段归属不符合查看语义 | 重组为查看分组 |
| 表单页字段堆到 30 个 | 用户找不到重点、错误率高 | 拆步骤或分组折叠 |
| 一页混多类型（上面看板 + 下面列表 + 右侧表单） | 注意力分散、无主任务 | 拆页或用页签 |
| 只读主数据做成可编辑列表 | 用户误以为能改 | 去掉写操作，标「来源：外部系统」 |
| 弹窗里做多步流程 | 层级混乱 | 改抽屉或独立页面 |
| 状态只在「成功」时考虑 | 上线后裸奔 | 按 §二·12 与 `interaction-design.md` 补齐 |
