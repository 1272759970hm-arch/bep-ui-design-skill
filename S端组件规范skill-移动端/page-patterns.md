# BEP-S 常见页面模板

> 这些模板只是**结构参考起点**（对应 SKILL.md 的 Step 2）。真正决定页面长什么样的是 Step 3 的信息架构分析和 Step 4 的组件库检索——**不要因为模板里列了某个模块，就不假思索地塞进业务用不上的东西**。如果业务需求只需要模板里的三个模块，就只做三个，模板剩下的模块直接忽略。
>
> ⚠️ **这份文件只回答"页面结构"（有哪些模块、什么顺序），不回答"页面看起来有没有设计感"——这两件事是分开的（2025-08 新增区分，二次更正见下）。** Home Page 模板、以及任何运营/活动/内容推荐类需求（本文件没有对应页面级模板，因为这类页面结构本身高度自由），落地前必须先看 [visual-design-reasoning.md](visual-design-reasoning.md) 做完整的设计推理（Business Goal → Page Role → ... → Page Composition），[c-end-visual-design.md](c-end-visual-design.md) 是这套推理里 Visual Strategy 环节的具体规则库——只搭出模板里的组件结构、不管视觉构成，就是"所有页面都长一个样、像组件拼装"的直接成因。**Page Role 分三级：PR1(首页/运营活动页) / PR2(列表/详情/搜索/推荐/看板) / PR3(表单/设置/操作)**，定义见 `visual-design-reasoning.md` 第2节。List/Detail/Search/Dashboard 对应 PR2，需要基本节奏感（见 `c-end-visual-design.md` 第5节）；Form/Settings 对应 PR3，维持模板原本的规整结构就是正确答案，不需要额外看那两份文件。
>
> ⚠️ **这份文件也新增了「Composition Patterns」章节**（页面最下方）——那是**模块级**的组件组合方式（比如"图片+标题+价格+CTA"组成一个"商品Hero"），跟这里的**页面级**结构模板是两个不同颗粒度的东西，两者配合使用：先按本文件的页面模板确定大结构，再用 Composition Pattern 把某个模块具体的组合方式定下来。

## 模板只规定结构，不保证组件存在（2025-08 实测新增，重要）

下面每个模板的"常用组件"列表，写的是**这类页面通常需要什么样的功能模块**，不是"这些组件在库里都有真实版本可以直接用"的保证。这两件事必须分开：模板负责回答"这个页面结构上需要几块内容、顺序是什么"，`component-library.md` 负责回答"这块内容现在到底有没有真实组件可复用"。

真实案例：Form Page 模板下面列了"多行文本输入"这类字段，但实测确认库里**没有独立的 Textarea/多行文本真实组件**——如果看到模板提到就想当然认为组件库一定有对应的东西，会直接导致"相似组件魔改"（拿 Input 拉高冒充）。

**因此，模板里列出的每一个组件，落地前都必须过一遍 Component Availability Check**：去 `component-library.md` 查它的真实状态（`REAL_COMPONENT`/`REMOTE_COMPONENT`/`INSTANCE`/`SPEC_ONLY`/`NOT_FOUND`），不能因为模板提到了就跳过这一步。模板对每个组件的注记方式是"组件通用名（真实性未知，需查 component-library.md）"，除非该组件在 component-library.md 里已经有明确记录，才可以在模板里直接标注它的确认状态。

## List Page 列表页

- **页面结构**：NavBar（标题+可选右侧操作）→ 可选 SearchBar/Tab筛选 → Cell 或 Card 重复堆叠(+ Divider) → 触底加载/无更多 → 无数据时替换为 Empty
- **常用组件**：NavBar、Cell/Card、Divider、SearchBar(可选)、Tab标签栏(可选筛选)、Empty
- **信息层级**：列表项标题/关键字段 > 状态标签(Tag) > 次要信息 > 行内操作(Button文字按钮)
- **主要操作**：点击行进入详情、下拉刷新
- **次要操作**：筛选、排序、搜索
- **适用场景**：订单列表、工单列表、消息列表、通用数据列表
- ⚠️ **PR2级页面**：需要基本节奏感（见 c-end-visual-design.md 第5节），不要所有列表项做成完全等重的Cell堆叠，可以让紧急/异常状态的条目视觉上更突出。

## Detail Page 详情页

- **页面结构**：NavBar（标题+返回）→ 核心信息区(Card) → 分组信息(Cell 逐行) → 可选 Timeline/Steps(流程记录) → 底部操作栏(Button)
- **常用组件**：NavBar、Card、Cell、Divider、Timeline 或 Steps(按是否需要历史时间线选择)、Tag(状态标记)、Button
- **信息层级**：核心状态/标题 > 关键字段分组 > 流程记录 > 底部操作
- **主要操作**：底部主操作按钮(如处理、确认)
- **次要操作**：查看更多记录、联系相关方
- **适用场景**：订单详情、工单详情、审批详情（参考库内示例页"履约任务详情"的模块划分，但那是示例业务页，不能直接当组件复用，只能参考其模块拆分方式）
- ⚠️ **PR2级页面**：核心状态/标题模块可以适当放大突出，不需要跟其余Cell信息模块视觉权重完全一致。

## Form Page 表单页

- **页面结构**：NavBar → 分组标题 → Cell/Input/Radio/Checkbox/Upload/Switch/选择触发行 按字段类型逐行排列(+ Divider) → 底部固定提交按钮(Button)
- **常用组件（Component Availability Check 结果，2025-08 信息登记表单实测已核实，可直接引用不用重查）**：
  - NavBar → `INSTANCE` 已确认，直接复用
  - Input（单行文本） → `INSTANCE` 已确认，直接复用
  - 选择触发行（对接 Picker/DatePicker 的字段） → `INSTANCE` 已确认，是一个证据丰富的独立组件族，见 component-library.md 第6节
  - Radio → `INSTANCE` 已确认（未选中/选中两态都验证过）
  - Checkbox（胶囊按钮形态，适合多选标签） → `INSTANCE` 已确认（未选中/选中两态都验证过）
  - Checkbox（20×20 小方框形态） → 仅"选中"态是 `INSTANCE`，**未选中态 NOT_FOUND**，需要按 SPEC_FRAME 规则手绘
  - Switch → `INSTANCE` 已确认（未在此次测试里实际用到，但组件库里状态齐全）
  - Upload → `INSTANCE` 已确认
  - **多行文本/Textarea → NOT_FOUND，库里没有独立组件**，不要假设它存在，走"组件缺失清单"流程或明确标注为 Input 的变形使用
  - **Primary Button 提交按钮 → NOT_FOUND**（已穷举验证，见 component-library.md 第5节），按钮规范画板可以当搭建依据
- **信息层级**：必填字段(星号标记，通过 Input/选择触发行内置的星形子组件切换显隐即可实现，不需要额外组件；⚠️2025-08更正：星号排在标题文字**后面**，如"配送员*"，不是网页惯例的"*配送员"，详见 component-library.md) > 选填字段 > 说明性文字
- **主要操作**：提交
- **次要操作**：保存草稿、取消
- **适用场景**：个人信息填写、请假/外勤申请、报名表单
- ⚠️ **PR3级页面**：保持规整的组件化结构就是正确答案，不需要额外的视觉设计投入（见 visual-design-reasoning.md 第1节）。

## Search Page 搜索页

- **页面结构**：SearchBar(激活态，常置顶替代NavBar或与NavBar组合) → 搜索历史/热门推荐(初始态) → 结果列表(Cell/Card) → 无结果时 Empty(搜索无结果场景)
- **常用组件**：SearchBar、Cell/Card、Tag(历史标签)、Empty
- **信息层级**：搜索框 > 结果列表 > 历史/推荐(仅在未输入时展示)
- **主要操作**：输入并搜索
- **次要操作**：清空历史、点击历史词再次搜索
- **适用场景**：商品搜索、地址搜索、内容检索
- ⚠️ **PR2级页面**。

## Dashboard 看板页

- **页面结构**：NavBar → 关键指标卡片(Card) → 图表区(数据图表组件集) → 明细列表(可选)
- **常用组件**：NavBar、Card、图表组件(环形图/折线图/柱状图/雷达图/仪表盘等，按数据形态选)、Cell(明细)
- **信息层级**：核心KPI数字 > 趋势图表 > 明细数据
- **主要操作**：切换时间范围、下钻查看明细
- **次要操作**：导出、筛选维度
- **适用场景**：运营看板、数据统计页
- ⚠️ **PR2级页面**：节奏体现在"核心KPI(大、突出)→图表(中密度)→明细列表(高密度)"的层级递进，见 c-end-visual-design.md 第5节。
- **⚠️ 注意**：图表组件集画板基准是1920×1080(PC/大屏)，移动端使用前必须先跟用户确认自适应/裁剪规则，不要假设能直接等比缩放到手机屏幕还保持可读性

## Home Page 首页

- **页面结构**：NavBar或无NavBar(沉浸式) → SearchBar(可选) → Carousel(推荐位，可选) → Grid(功能入口) → TabBar(底部导航，页面级容器)
- **常用组件**：SearchBar、Carousel、Grid、TabBar、Card(推荐内容)
- **信息层级**：搜索/核心入口 > 功能矩阵 > 推荐内容
- **主要操作**：点击功能入口
- **次要操作**：搜索、浏览推荐
- **适用场景**：App首页、频道首页
- ⚠️ **这是 PR1 级页面**：只搭出上面这个组件结构不够，必须同时执行 [c-end-visual-design.md](c-end-visual-design.md) 第3节（首页必须有一个视觉焦点模块，体量明显大于Grid下面的普通列表卡片）和第2节（背景不能纯白到底），否则会做成"能用但没有第一眼抓手"的首页。

## Settings Page 设置页

- **页面结构**：NavBar → Cell 逐行设置项(+ Divider)，右侧按设置类型接 Switch(开关类) / 箭头(跳转类) / 文字(展示当前值类)
- **常用组件**：NavBar、Cell、Switch、Divider
- **信息层级**：常用设置 > 账号/安全类设置 > 关于/版本信息
- **主要操作**：切换开关、点击跳转二级设置
- **次要操作**：退出登录（通常在页面底部，视觉上与其他设置项区分）
- **适用场景**：通知设置、账号设置、隐私设置
- ⚠️ **PR3级页面**：保持规整结构即可，不需要额外视觉设计投入。

## Empty Page 空状态页

- **页面结构**：NavBar(可选) → 居中的 Empty 插画+文案 → 可选引导操作(Button)
- **常用组件**：Empty(按语义选8种插画之一)、Button(引导操作，可选)
- **信息层级**：插画 > 主文案 > 辅助说明 > 引导操作
- **主要操作**：按插画语义决定——网络异常给"重试"、无数据给"去添加"等
- **次要操作**：返回上一页
- **适用场景**：列表无数据、网络异常、定位失败、功能维护中、权限拒绝、搜索无结果

## 组合页面怎么处理

真实业务页面经常是多个模板的组合（比如"列表页 + 内嵌搜索"、"详情页 + 表单编辑态"）。遇到这种情况：先按 SKILL.md Step 3 独立做信息架构分析，再从上面几个模板里各取需要的模块拼，不要强行整体套用某一个模板的完整结构。

```

  组头：组名 16px Semibold 左 + 状态「未完成·1/2」12px 右（#9199A2）
```

这张卡片同时回答了「列表项长什么样」和「详情页子条目长什么样」——同一 anatomy 在两处复用，**不要为详情页重新发明第二种卡片**。

### D. 跨页面设计规律（9 条，全部实读）

1. **灰底 + 白 section 堆叠**是页面宏观构成。白色分节之间不加间隙，靠"分节标题行 h60"分界；只有独立卡片之间才用 gap12。
2. **卡中卡**：白卡内的信息块用灰底再包一层（头部卡的任务信息、弹层里的说明块都是这个手法）。精确规格（2026-11-04 从 `10293:34203` 任务信息块实读补齐）：容器 `#F7F8FA r8 px16 py12`，块内 gap 8；**kv 行高 28px（py3，items-center），label 与 value 间距 12px**——行间距是 28+8=36px，不要写成"行高 24 + gap 4"（那会撑到 60px，2026-11-04 实测翻过车）。设计稿 kv 字号为 16px，新页面按 token 用 14px 亦可，行高规格不变。
3. **h60 是节奏锚点**：分节标题行、Cell、表单行都是 60px——页面纵 rhythm 由它统一。
4. **筛选胶囊 ≠ 状态 Tag**（重要，2026-11 修正）：筛选胶囊选中态 = 品牌色 **14% tint 底 + 品牌色文字**（`rgba(0,178,178,0.14)`）；语义状态 Tag = 主色 **10% 浅底 + 主色文字** 的小标签（2026-11-05 实测更正，原记 16%）。两者形态接近但角色不同，不要把筛选胶囊做成实心品牌色。
5. **状态语义色三件套**（Arco 体系，实读验证）：异常/闭环红 `#F53F3F`、警告橙 `#FF7D00`（浅档 `#FFA645`）、完成绿 `#00B42A`；浅底一律 = 主色 16%。黄 `#FFD333` 在本业务里是"打卡/引导"专用色，不当归伞语义色使用。
6. **文字色实际主力三级**：`#22262F`（标题/正文）、`#6F879E`（次强调）、`#9199A2`（辅助/占位）。旧稿还混有 #4E5969/#86909C/#5C6673 等变体——**新页面收敛到 token 的 text.5/4/3，不要扩散第四种灰**。
7. **行高实测配对**：单行控件（label/按钮/Cell）行高≈字号；**多行正文 14px→22px（×1.57）**；16px→20/22。组件库标注的 ×1.4 只适用于长文排版，列表/卡片场景按上面的配对来（修正了旧记录"一律 ×1.4"）。
8. **卡片底部操作行**：0.5px 分隔线之上放"左右文字操作 + 右箭头"，左操作常规深色、右操作品牌色——这是任务/工单卡片的固定收尾，不要用整块按钮替代。
9. **FAB 与底部双按钮栏共存**时：FAB 底边距底部操作栏顶 34；双按钮栏 = 48h + px16 + gap15，按钮各 164 宽（等分）。单按钮时通栏。

### E. 置信度与冲突登记

- 本节所有数值 `FOUND_IN_DRAFT`（真实设计稿实读），可信度等同 `FOUND_IN_FIGMA`。
- 与组件库的冲突（页面底色、筛选胶囊选中态、品牌色 #00B2B2 残留）已登记进 `design-system-conflicts.json` 与 `constraints.md` C-67…C-73，处理优先级见 `constraints.md` 冲突优先级表。
- 设计稿正文行高大量为 `leading-[normal]`（浏览器默认）——**不要模仿**，按第 7 条配对落值。

## Composition Patterns（构成模式）

> 2025-08 新增，对应 `visual-design-reasoning.md` 第12节。这一节和上面的页面模板是**两个不同颗粒度**的东西：上面的模板是"一整个页面由哪几块内容组成"（page-level），这里是"一个模块内部，几个真实组件+文本+图片怎么组合"（module-level）。

**Composition Pattern 不是组件**，不进 `component-registry.json`，Figma 里也不需要有对应的东西——它是"已有材料的组合配方"。使用时必须遵守：
1. 组合的原材料只能是：真实 BEP-S Component（Card/Button/Tag等）+ 纯文本 + 图片（如需要，按 `c-end-visual-design.md` 第2节标注是否占位图）+ 无语义容器（div/section）+ Spacing Token。
2. **不允许修改任何真实 Component 本身的属性**去凑这个 Pattern——比如下面 "Product Hero" 用到 Card，Card 依然要遵守"无投影无描边"的既有规则，不能因为要塞进这个 Pattern 就给它加投影。
3. `data-bep-component` 标注这个模块用的 Composition Pattern 名称，`data-bep-status` 标 `AI_DESIGN_DECISION`，内部每个真实组件各自的 `data-bep-status` 不变（该是 `REMOTE_INSTANCE` 还是 `REMOTE_INSTANCE`，不因为参与了 Pattern 组合就改变自己的真实性等级）。

**已有的 Composition Pattern（可以直接用，也可以按同样的方式新增，新增的要追加进这份清单）**：

| Pattern | 组合公式 | 典型用途 | 适用 Page Role |
|---|---|---|---|
| **Primary Action Hero**（主操作焦点，2025-08新增） | Icon(大) + Title + Subtitle + 渐变背景，整体可点击 | 页面唯一的高频核心动作入口（如"扫码核销"），当这个动作本身就是 Primary Visual Focus 时用，比 Product Hero 更简洁、不依赖图片素材 | PR1 焦点模块 |
| **Alert Banner**（异常提醒条，2025-08新增，NOT_FOUND组件缺口） | Icon(语义色) + Text(数量+说明) + Arrow | 从常规统计数据里单独摘出需要立即处理的异常状态，不跟"正常流转中"的数字混在一起 | PR1/PR2 |
| **Product Hero**（商品焦点） | Image + Title + Price + CTA(Button) | 商品详情页头部、首页焦点模块里的单品推荐 | PR1 焦点模块 / PR2 详情页头部 |
| **Promotion Block**（活动板块） | Background(色块/渐变) + Campaign Title + Product(s) + CTA(Button) | 活动页/首页里的促销板块 | PR1 |
| **Featured Category**（精选分类） | Title + Category(Grid或横向滚动) + Image | 首页品类导航区，比金刚区更强调视觉（配图） | PR1 |
| **Content Story**（内容叙事） | Image + Large Title + Supporting Text | 编辑推荐、专题内容、资讯型模块 | PR1 / PR2 内容流 |
| **Stat Highlight**（数据焦点） | 大字号Number + Label，多个并排 + 分割线 | KPI概览、首屏统计数据（参考"履约值守台"demo的KPI行） | PR1 焦点模块内 / PR2 看板头部 |
| **Task Card**（任务卡片） | 状态角标(Tag) + Title-row(Store/Title+普通标签) + Cell(信息行) + Product-row(可选) + Action-row(说明文字+Button) | 订单/工单/任务类列表项，比纯 Cell 堆叠信息层次更丰富 | PR2 列表 |
| **Empty State Block**（空状态区块，2025-08新增，对应`visual-design-reasoning.md`第8.4节UX状态设计） | Empty(真实组件，8种插画场景任选) + 主文案 + 辅助说明 + 引导操作(Button，可选) | 任何展示数据的模块，数据为空时的替代呈现——不要留白，也不要临时手绘一个占位图 | 任意 PR |

这份清单不是穷举，遇到新的组合需求时，按上面三条使用规则自己定义新的 Pattern，取一个能望文生义的名字，补进这张表，方便以后复用同一个组合方式而不是每次重新设计。
